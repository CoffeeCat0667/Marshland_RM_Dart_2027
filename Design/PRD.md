## 2. 项目概述

本项目用于开发 RoboMaster 2027 飞镖系统的镖架控制主程序。程序负责镖架各机构的统一控制、动作协调、状态管理、通信交互和故障处理，并直接控制相关电机、舵机及输入信号。

系统包含以下主要机构和功能域：

- 蓄力机构
- 换弹机构
- 供弹机构
- 发射机构
- 变力机构
- YAW 轴角度调整
- 电机底层驱动、编码器处理和闭环控制
- GPIO 高低电平信号读取
- Web 前端及 HTTP、WebSocket 交互
- CAN、IIC 和舵机控制

## 3. 产品目标

1. 实现飞镖系统镖架的完整自动发射流程。
2. 支持手动控制、调试和校准模式。
3. 支持连续发射。
4. 实现对电机、舵机、编码器、限位开关和 GPIO 输入的统一管理。
5. 为各机构提供可观察、可控制、可配置和可诊断的运行状态。
6. 在通信异常、动作超时或机构异常时进入规定的安全状态。
7. 支持在 Ubuntu 22.04 ARM64 主机上稳定运行。
8. 支持 PID 参数持久化保存，避免设备重启后丢失已配置参数。

## 6. 系统角色与外部对象

系统需要与以下外部对象交互：

1. **Web 前端**
   - 提供人工操作、状态查看、参数配置、调试和校准入口。
   - 通过 HTTP 和 WebSocket 与主程序交互。

2. **CAN 总线设备**
   - CAN 总线上的设备类型、节点数量和现有协议已经确定。
   - 主程序负责按照既定协议进行数据收发和状态管理。

3. **PCA9685A 舵机驱动器**
   - 通过 IIC 与主程序连接。
   - 负责输出 MG996R 舵机控制信号。

4. **电机与编码器**
   - 主程序直接控制电机。
   - 主程序读取编码器数据并完成闭环控制相关处理。

5. **GPIO 输入设备**
   - 包括限位开关及其他需要接入的高低电平信号。

6. **视觉系统**
   - 视觉系统负责向 YAW 控制链路提供指定 YAW 控制量（单位 rpm）。
   - 视觉系统通过一个 `bool` 型 YAW 到位信号反馈状态：`True` 表示 YAW 到位，`False` 表示未到位或已清除。
   - 自动发射流程仅在 YAW 到位信号为 `True` 且发射控制权满足 `SBUS > WEB > 自动流程` 时触发对应发射动作。
   - 每次发射完成后，由主控制程序将 YAW 到位信号设回 `False`。
   - 停止发射标志在视觉系统正常回传 YAW 到位时由视觉系统清为 `False`；若等待 30 s 超时且视觉系统仍无响应，则由控制主系统将 YAW 到位信号置为 `True` 并将停止发射标志清为 `False`。

7. **天地飞 ET16S 遥控系统**
   - ET16S 接收机通过 SBUS 信号提供手动控制和软件急停触发入口。

## 7. 系统运行模式

### 7.1 初始化模式

系统启动后进入初始化流程，完成以下工作：

- 加载系统配置。
- 加载持久化的 PID 参数。
- 初始化 CAN 通信。
- 初始化 IIC 和 PCA9685A 舵机驱动器。
- 初始化电机、编码器和 GPIO 输入。
- 建立各机构的初始状态。
- 检查必要设备和输入信号是否可用。

初始化未完成或初始化失败时，不得进入正常发射流程。

### 7.2 待机模式

系统完成初始化后进入待机模式。待机模式应：

- 维持设备在安全状态。
- 提供状态查询和参数查询。
- 接收手动控制、自动发射、参数与校准请求；模式切换沿用既有路由，不新增独立模式路由。
- 不得在未满足发射条件时执行发射动作。

### 7.3 自动发射模式

自动发射模式为固定总弹数 4 发的运行流程。程序开始运行后，按照 `Design/PEF.md` 执行：

1. 第 1 发：蓄力机构执行一次蓄力（`X` 秒），变力机构执行一次变力（`X` 秒）；通过视觉系统控制 YAW 电机转至指定值（单位 rpm）；视觉系统将 YAW 到位 `bool` 信号设为 `True` 后，视觉系统将停止发射标志设为 `False`，主程序在发射授权通过后执行发射动作；若等待超过 30 s 且视觉系统仍无响应，则由控制主系统将 YAW 到位信号置为 `True`、将停止发射标志设为 `False` 后按到位处理；发射完成后主控制程序将 YAW 到位信号设回 `False`。
2. 第 2 发：蓄力机构执行一次蓄力；换弹机构抬起并供弹；等待配置时间后换弹机构放下；变力机构执行一次变力；随后控制视觉 YAW。视觉到位时由视觉系统清除停止发射标志；若视觉系统超过 30 s 无响应，则控制主系统将 YAW 到位信号置为 `True`、按超时到位处理并将停止发射标志清为 `False`；之后仍须通过发射授权检查才可发射。
3. 第 3 发：执行与第 2 发相同的流程。
4. 第 4 发：执行与第 2 发相同的流程。

每一发均执行蓄力和变力，第 2 至第 4 发额外执行换弹和供弹。自动流程无额外固定发射间隔；各步骤完成且停止发射标志为 `False`、发射控制权获准后立即发射。

自动流程最多发射 4 发。停止发射标志在发射前待命状态为 `True` 时，不得执行实际发射或开始下一发。

### 7.4 手动控制模式

手动控制模式支持以下控制入口：

1. Web 前端控制：操作者通过 Web 前端对允许的机构或动作进行单独控制。
2. SBUS 遥控控制：操作者通过天地飞 ET16S 遥控系统的接收机 SBUS 信号对手动模式进行控制。

SBUS 手动控制需求：

- 主程序应能够接收并识别天地飞 ET16S 遥控系统接收机输出的 SBUS 信号。
- 主程序应能够将 SBUS 通道信号映射为规定的手动控制指令。
- SBUS 手动控制应支持手动模式的进入、退出及允许的机构动作控制。
- SBUS 信号的通道分配、控制量范围、模式切换方式和有效值范围由 `Design/Config.md` 7.1、7.2 明确，不在本 PRD 中展开；摇杆量为以 1024 为中心、有效范围 364～1684 的连续量，开关量仅取 364、1024、1684 三个值；「自动模式」开关置位时控制源为 `AUTO`，此时 SBUS 与 WEB 仍可介入自动流程。
- SBUS 信号无效、接收超时、接收机失联或触发失控保护时，不得继续执行依赖该信号的手动动作，并按照通信异常安全策略处理：降级至 WEB，重连后自动恢复 SBUS 最高控制权。
- SBUS 手动控制不得绕过系统安全约束、动作限位、发射前置条件和通信异常处理。
- 实际发射动作的控制优先级严格为：`SBUS > WEB > 自动流程`。
- SBUS 控制取得控制权时，正在执行的低优先级自动发射流程必须在当前硬件动作组完成后终止，不得暂停后恢复。

手动模式的所有控制入口均不得绕过系统安全约束、动作限位和通信异常处理。

### 7.5 调试模式

调试模式用于查看和验证以下内容：

- 电机控制状态。
- 编码器数据。
- PID 控制参数和控制状态。
- GPIO 输入状态。
- 限位开关状态。
- 舵机当前控制状态。
- CAN 和 IIC 通信状态。
- 各机构状态和动作执行结果。

### 7.6 校准模式

校准模式用于完成系统运行所需的机构、位置、角度、力度或相关参数校准。校准过程应能够反馈当前步骤、结果和失败原因。

具体校准项目和判定标准由 `Design/Config.md` 及后续校准设计确定。

### 7.7 故障模式

当检测到通信故障、动作超时、输入异常、控制异常或其他不可继续执行的问题时，系统进入故障处理流程，并向 Web 前端和相关通信接口提供故障状态。

故障恢复条件和自动恢复规则由 `Design/Config.md` 14.2 定义。

## 8. 机构功能需求

### 8.1 蓄力机构

1. 蓄力机构采用弹簧蓄力方式。
2. 主程序应能够启动、停止和查询蓄力动作。
3. 蓄力完成判据为：机构以恒定速度执行指定时间 `X` 秒。
4. `X` 秒应属于可配置参数，并支持读取、修改和持久化。
5. 蓄力动作应支持超时、停止、失败和异常状态反馈。
6. 蓄力完成后，系统才允许进入后续流程。

### 8.2 换弹机构

1. 换弹机构由四个舵机组成。
2. 换弹机构包含“抬起”和“放下”两个动作组。
3. 两个动作组分别对应四个舵机的角度信息。
4. 主程序应通过 PCA9685A 向四个舵机发送对应动作组的角度。
5. 主程序向 PCA9685A 发送动作组角度后 500 ms 判定到位。
6. 换弹动作应提供动作组、目标角度、执行状态和完成状态反馈。
7. 具体四个舵机的通道分配和角度数值由 `Design/Config.md` 定义。

### 8.3 供弹机构

1. 供弹机构由一个舵机组成。
2. 一次供弹动作包含两个舵机角度：角度一为待机角度，角度二为换弹位角度。
3. 一次供弹动作的时序为：由角度一切换到角度二，保持配置时间，再切换回角度一。
4. 舵机返回角度一后，系统判定本次供弹动作完成。
5. 供弹机构不要求判断“已供弹”状态。
6. 供弹机构不要求判断“卡弹”状态。
7. 两个角度的具体数值和舵机通道由 `Design/Config.md` 定义。

### 8.4 变力机构

1. 变力机构采用电机方案。
2. 主程序应能够设置变力目标并驱动变力机构执行。
3. 变力机构应支持必要的闭环控制、PID 控制和编码器处理。
4. 变力动作应提供目标值、当前值和执行状态；本机构不设专属异常处理，通用电机、PID 和 CAN 异常按 `Design/Config.md` 14.2 故障表处理。
5. 变力参数的范围、单位和校准方式由 `Design/Config.md` 5.5 定义。

### 8.5 发射机构

1. 发射机构通过发射机构的 `x` 号舵机执行发射动作；舵机的具体编号和参数由 `Design/Config.md` 定义。
2. 发射机构的“发射”动作定义为：`x` 号舵机由“待机”角度切换到“发射”角度，保持配置时间后再由“发射”角度切换回“待机”角度。
3. `x` 号舵机返回“待机”角度后，判定一次发射动作完成。
4. 自动发射、手动发射和故障自动恢复中的发射动作均必须遵守上述动作定义。
5. 故障自动恢复中，发射机构应仅执行三次上述发射动作；三次动作期间，其他机构的电机保持零力矩，其他舵机角度保持不变。
6. 发射前，系统应确认发射流程的前置步骤已经完成。
7. 发射动作应提供准备、执行、完成、失败和异常状态。
8. 发射机构舵机的安全保持规则见“安全与故障处理”章节。

### 8.6 YAW 轴角度调整

1. 自动发射流程的每一发都必须执行 YAW 轴调整。
2. YAW 轴由电机机构执行。
3. YAW 轴电机通过 CAN 接口进行闭环控制。
4. YAW 调整为发射前的必须步骤；SBUS 与 WEB 手动 YAW 控制遵循 `SBUS > WEB > 自动流程` 仲裁。
5. 必须等待视觉系统将 YAW 到位信号置为 `True` 才允许发射；等待超过视觉系统无响应超时（30 s）时按到位处理，在发射授权满足时允许发射。
6. YAW 轴的 CAN 节点、目标单位（rpm）、反馈值、范围和完成判据由 `Design/Config.md` 5.1、10 定义。

## 9. 电机、闭环和输入信号需求

### 9.1 电机直接控制

1. 主程序需要直接控制电机。
2. 项目需要一并设计各机构所需的电机底层驱动。
3. 主程序应支持电机启停、目标值设置、状态读取和异常处理。
4. 电机控制应受系统模式、机构状态和安全条件约束。

### 9.2 闭环控制与 PID

1. 主程序应支持电机闭环控制。
2. 主程序应支持 PID 参数配置、读取、修改和运行时使用。
3. PID 参数需要持久化保存，设备重启后应能够恢复。
4. PID 参数修改应具备必要的权限或模式限制，避免在不安全状态下直接影响发射动作。
5. PID 控制异常应能够被检测、反馈和处理。

### 9.3 编码器处理

1. 主程序应通过 CAN 接口读取和处理电机编码器数据。
2. 系统应能够提供编码器的当前值、变化状态和有效性状态。
3. 编码器异常应能够被识别并阻止相关机构继续执行不安全动作。
4. 编码器数据的单位、分辨率、方向和既有报文定义以 `Docs` 中的 CAN 设备资料为依据，并在 `Design/Config.md` 中固化。

### 9.4 GPIO 输入

1. 主程序应支持 GPIO 高低电平输入读取。
2. 限位开关通过 GPIO 端口读取高低电平。
3. 系统应支持接入限位开关。压力传感器不在本版本范围内；后续重新纳入时必须增加独立接口设计并同步更新 `PRD.md`、`PEF.md`、`Interface.md` 和 `Config.md`。
4. 系统应能够向上层提供 GPIO 输入的当前电平和状态变化。
5. 限位开关的具体编号、有效电平和触发后的动作由 `Design/Config.md` 8.1 定义。

## 10. 舵机与 IIC 需求

1. 主程序通过 IIC 连接 PCA9685A 舵机驱动器。
2. PCA9685A 相关接口和实现参考 `Lib/PCA9685A`。
3. 主程序通过 PCA9685A 控制 MG996R 180°舵机。
4. 系统应能够设置、读取和管理舵机目标角度。
5. 系统应支持发射角度、换弹动作组角度和供弹动作角度的管理。
6. 系统应支持发射角度和安全保持角度的管理。
7. 舵机异常或 IIC 通信异常应能够被检测和反馈。
8. PCA9685A 地址、舵机通道、脉宽参数和角度校准参数以 `Lib/PCA9685A` 中的现有资料为参考，最终配置在 `Design/Config.md` 中确定。

## 11. CAN 通信需求

1. 主程序使用 SocketCAN 进行 CAN 数据收发。
2. 电机和编码器通过 CAN 接口接入系统。
3. YAW 轴电机通过 CAN 接口进行闭环控制。
4. PID 控制对象包括所有电机；其他控制对象预留，当前版本不实现。
5. 主程序应支持既定 CAN 节点和既有 CAN 协议。
6. CAN 既有协议的设备资料和报文定义位于 `Docs` 目录。
7. 主程序应能够处理控制指令、状态反馈、心跳、错误和超时信息。
8. CAN 通信状态应能够被查询和反馈。
9. CAN 通信中断或超时应触发规定的安全处理。
10. CAN 节点清单、CAN ID、数据字段、周期和超时阈值以 `Docs` 中的既有协议为依据，并纳入 `Design/Config.md`。

## 12. Web 前端需求

### 12.1 总体要求

1. Web 前端属于本项目的一部分。
2. 系统应提供 HTTP 交互能力。
3. 系统应提供 WebSocket 交互能力。
4. Web 前端应能够完成控制、状态查看、参数管理、调试和校准操作。
5. Web 前端静态资源由主程序直接提供，具体部署参数由 `Design/Config.md` 11.1 定义。

### 12.2 控制功能

Web 前端至少应提供以下操作入口：

- 系统初始化和状态查看。
- 自动发射启动（固定四发）和停止发射控制。
- 手动控制（动作集见 `Design/Config.md` 11.4）。
- 蓄力、换弹、供弹、变力和发射机构的状态查看。
- YAW 目标设置（单位 rpm，遵循 `SBUS > WEB > 自动流程`）和状态查看。
- 舵机角度设置和状态查看。
- PID 参数查看、修改和保存（仅 WEB 控制源，手动或调试模式）。
- 调试状态查询入口。
- 校准操作入口（`/api/calibration`）。
- 故障、报警和通信状态查看。
- 软件急停触发和故障人工确认恢复。

### 12.3 实时状态

WebSocket 用于提供必要的实时状态更新，包括但不限于：

- 当前系统模式。
- 当前发射流程步骤。
- 各机构状态。
- 电机目标值和反馈值。
- 编码器状态。
- GPIO 和限位开关状态。
- 舵机状态。
- CAN、IIC 和系统故障状态。
- 急停和人工确认状态。

具体 HTTP 路由、WebSocket 消息格式和前端页面由 `Design/Interface.md` 与 `Design/Config.md` 定义，两者当前均为正式稿。

## 13. 发射流程需求

### 13.1 单次发射

本版本自动流程的第一发为单次发射流程：

1. 检查系统处于允许发射的模式和状态。
2. 执行蓄力和变力步骤。
3. 通过视觉系统控制 YAW 电机转至指定值。
4. 等待视觉系统将 YAW 到位 `bool` 信号设为 `True`；视觉正常回传到位时由视觉系统清除停止发射标志。
5. 若等待视觉到位超过 30 s 且视觉系统仍无响应，控制主系统将 YAW 到位信号置为 `True`，按超时到位处理，并将停止发射标志设为 `False`。
6. 检查实际发射控制权、停止发射标志、故障状态和软件急停状态。
7. 前置条件满足后，执行发射机构发射动作。
8. `x` 号舵机回到“待机”角度后判定本次发射完成；由主控制程序将 YAW 到位信号设回 `False`。

YAW 未到位且未达到 30 s 超时、控制权未获准、停止发射标志为 `True` 或系统处于故障/急停状态时，不得触发发射。

### 8.7 视觉迟到状态处理

1. 视觉系统在 30 s 正常回退完成后恢复时，迟到视觉状态只能影响尚未执行实际发射的当前发次。
2. 若当前发次尚未执行实际发射，则主控制程序按最新视觉状态重新执行 YAW 到位检查；未重新满足到位和发射授权条件前，不得发射。
3. 若当前发次已经完成实际发射，则迟到视觉状态不得回滚已完成动作，仅记录诊断事件。


### 13.2 连续发射

1. 系统应支持连续发射，固定总数为 4 发。
2. 第 1 至第 4 发均执行蓄力和变力。
3. 第 1 发的顺序为：蓄力 → 变力 → 视觉 YAW → 等待到位或 30 s 无响应超时回退（超时由控制主系统将 YAW 到位置为 `True`）→ 发射。
4. 第 2 至第 4 发的顺序为：蓄力 → 换弹抬起 → 供弹 → 等待配置时间 → 换弹放下 → 变力 → 视觉 YAW → 等待到位或 30 s 无响应超时回退（超时由控制主系统将 YAW 到位置为 `True`）→ 发射。
5. 每次发射均由发射授权优先级和安全条件约束；连续发射无额外固定间隔。
6. 视觉系统正常将 YAW 到位信号设为 `True` 时，由视觉系统清除停止发射标志；若 30 s 超时且视觉系统仍无响应，则由控制主系统将 YAW 到位信号置为 `True` 并清除停止发射标志。
7. 自动流程只在 FIRE_READY 检查停止发射标志；标志为 `True` 时不得实际发射或开始下一发，标志为 `False` 且授权通过时才可发射。
8. SBUS 接管时，原自动流程在当前硬件动作组完成后终止，不暂停、不恢复。
9. 故障、通信异常、输入异常或软件急停时进入相应安全/故障流程，禁止不符合授权的后续发射。
10. 完整流程状态和异常转移以 `Design/PEF.md` 为准。

## 14. 安全与故障处理

### 14.1 通信异常安全策略

当发生规定的通信中断或通信超时时：

1. 电机全部设置为零力矩。
2. 舵机保持当前角度不变。
3. 禁止改变发射机构舵机的角度值。
4. 系统应反馈通信异常状态。
5. 自动发射和连续发射应停止或禁止继续推进。

### 14.2 输入和动作保护

1. 限位开关输入参与相关机构的安全判断；压力传感器不在本版本范围内。
2. 电机闭环异常、编码器异常、动作超时和控制目标异常应被识别。
3. 未完成初始化或不满足发射前置条件时，不得执行发射。
4. 系统不新增硬件急停方案。
5. 软件急停触发入口包括 Web 前端和 ET16S 遥控器。
6. 实际发射动作的控制优先级严格为：SBUS 遥控控制 → WEB 前端控制 → 自动流程控制。
7. 一般故障允许自动恢复；自动恢复流程为：蓄力机构两个电机回零（运行至两个限位开关均为低电平）→ 仅发射机构执行三次发射动作 → 换弹机构置于抬起位。
8. 自动恢复执行三次发射动作期间，除发射机构外，其他机构的电机保持零力矩，其他舵机角度保持不变。
9. 一般故障自动恢复完成后，系统进入手动状态；自动发射流程不得自动恢复或继续。
10. 软件急停触发后，所有电机必须持续发送零力矩 CAN 帧；换弹机构必须置于抬起位；系统必须拒绝一切操作发射机构舵机的指令。
11. 软件急停必须经 Web 前端或 ET16S 遥控器人工确认后才允许解除。
12. 人工确认解除软件急停后，换弹机构执行抬起动作，蓄力机构两个电机执行回零动作；蓄力机构仅在两个限位开关均为低电平时判定回零完成。
13. 人工确认解除软件急停后不需要重新初始化，且不得自动恢复原自动发射流程。
14. 一般故障自动恢复及软件急停恢复期间，均不得启动或继续自动发射。

### 14.3 保护参数

以下保护参数已由 `Design/Config.md` 定义，本 PRD 不重复具体数值：

- 各机构最大动作时间（`Config.md` 第 4 节）。
- 电机最大电流或力矩限制（`Config.md` 4、5.2）。
- 最大位置误差（视觉系统内部 YAW 到位判据，`Config.md` 4）。
- 舵机角度范围和安全角度（`Config.md` 9.2、9.3）。
- 限位开关触发后的处理方式（`Config.md` 8.1）。
- CAN、IIC、HTTP 和 WebSocket 超时阈值（`Config.md` 4）。
- 压力传感器不在本版本范围内，其参数不适用。

## 15. 性能与实时性需求

1. 系统最长控制周期不得超过 100 ms。
2. 电机控制、状态采集、机构控制和通信处理不得违反该周期约束。
3. Web 前端状态更新应满足操作和调试所需的实时性。
4. 具体控制周期、PID 周期、状态反馈周期和通信周期由 `Design/Config.md` 第 4 节定义。

## 16. 参数与数据持久化

1. 每个电机的 PID 参数必须支持持久化保存。
2. 系统重启后应能够恢复有效的电机 PID 参数。
3. 除电机 PID 参数外，系统额外预留 100 个持久化变量。
4. 蓄力时间 `X`、发射角度、YAW 目标参数、变力参数和校准参数均按 `Design/Config.md` 13.3 持久化。
5. 参数加载失败、参数损坏或参数越界时，按 `Design/Config.md` 13.1 与 14.2 的故障策略处理。
6. 持久化变量的命名、类型、存储格式、存储位置和版本迁移策略由 `Design/Config.md` 13.1、13.2、13.3 定义。

## 17. 验收目标

### 17.1 基础运行

- 能在 Ubuntu 22.04 ARM64 环境启动。
- 能完成必要的设备和通信初始化。
- 能显示当前系统状态和初始化结果。

### 17.2 机构控制

- 能够分别控制蓄力、换弹、供弹、变力和发射机构。
- 能够读取编码器、GPIO 和限位开关状态。
- 能够通过 PCA9685A 控制 MG996R 舵机。
- 能够执行 YAW 轴角度调整。

### 17.3 自动流程

- 能够完成自动发射流程，整个流程固定 4 发。
- 第 1 发顺序满足“蓄力 → 变力 → YAW 调整 → 发射”。
- 第 2 至第 4 发顺序满足“蓄力 → 换弹/供弹 → 变力 → YAW 调整 → 发射”。
- 每一发均等待 YAW 到位；视觉系统无响应超过 30 s 时按到位处理。
- 任一前置步骤异常时，不继续执行后续步骤。

### 17.4 控制和调试

- 能够使用 Web 前端执行手动控制。
- 能够进入调试和校准模式（进入无需模式前提，急停或活动故障锁定时除外）。
- 能够查看和修改 PID 参数。
- PID 参数重启后能够恢复。

### 17.5 安全处理

- 通信异常时电机进入零力矩状态。
- 通信异常时舵机角度保持不变。
- 通信异常时禁止改变发射机构舵机角度值。
- 动作超时、编码器异常或输入异常能够被反馈和处理。

## 19. 当前待确认事项

以下事项已根据当前补充信息明确。具体硬件参数、通道号、角度值、CAN ID、PID 数值和阈值不在本 PRD 中体现，统一由 `Design/Config.md` 定义；`[待定]` 项为预留接入点，在部署或联调前补齐。

1. **换弹机构：已明确。** 由四个舵机组成，包含“抬起”和“放下”两个动作组。主程序向 PCA9685A 发送动作组角度后 500 ms 判定到位。
2. **供弹机构：已明确。** 由一个舵机组成；角度一切换至角度二后保持配置时间，再返回角度一，完成一次供弹动作；自动流程第 2 至第 4 发从供弹动作触发起等待配置时间后再执行换弹放下（时序数值见 `Design/Config.md` 4、9.2）。
3. **YAW 与视觉：已明确。** YAW 轴由 CAN 闭环电机执行，视觉系统输出 YAW 目标控制量（单位 rpm），其内部到位判据为像素误差；视觉系统通过 `bool` 型 YAW 到位信号反馈状态，值为 `True` 时表示到位；自动流程必须等待该信号为 `True`，等待超过 30 s 且视觉仍无响应时由控制主系统将该信号置为 `True` 并按到位处理；每次发射完成后由主控制程序将其设回 `False`。
4. **四发自动流程：已明确。** 每一发均执行蓄力与变力；第 1 发为蓄力、变力、视觉 YAW 到位后发射；第 2 至第 4 发为蓄力、抬起换弹、供弹、等待、放下换弹、变力、视觉 YAW 到位后发射；总弹数固定为 4。
5. **发射动作：已明确。** `x` 号舵机由“待机”角度切换到“发射”角度，保持配置时间后切换回“待机”角度；回到待机角度后判定一次发射完成（保持时间见 `Design/Config.md` 4、9.2）。
6. **停止发射标志清除：已明确。** 视觉系统正常回传 YAW 到位时由视觉系统将停止发射标志清为 `False`；若等待 30 s 超时且视觉系统仍无响应，则由控制主系统将 YAW 到位信号置为 `True` 并将停止发射标志清为 `False`；自动流程在 FIRE_READY 扫描该标志，为 True 时不发射，为 False 且授权通过时发射。
7. **控制仲裁：已明确。** 实际发射动作的控制优先级严格为 `SBUS > WEB > 自动流程`；初始控制源为 `AUTO`，存在 WEB 连接时为 `WEB`，SBUS「自动模式」标志置位时为 `AUTO`（此时 SBUS 与 WEB 仍可介入自动流程），否则按 `SBUS > WEB` 选择；SBUS 失联时降级至 WEB，重连后自动恢复 SBUS 最高控制权；SBUS 接管时原自动流程在当前硬件动作组完成后终止，不暂停、不恢复；具体 SBUS 通道映射不在本 PRD 中体现。
8. **一般故障恢复：已明确。** 自动执行蓄力机构两个电机回零（两个限位开关均为低电平）；随后仅发射机构执行三次发射动作，其他机构的电机保持零力矩、其他舵机角度保持不变；最后换弹机构抬起；恢复完成后进入手动状态。
9. **软件急停：已明确。** 前端或遥控器触发；所有电机持续发送零力矩 CAN 帧；换弹机构抬起；拒绝一切发射机构舵机操作指令；人工确认解除后换弹机构抬起、蓄力机构两个电机回零，不需要重新初始化，且不自动恢复原自动发射流程。
10. **具体参数：不在 PRD 中体现。** 各类参数、通道、角度、CAN 报文及阈值统一在 `Design/Config.md` 配置表中定义。
11. **验收标准：已具备可执行基线。** 逐项验收以本 PRD 第 17 节验收目标、`Design/PEF.md` 流程条款和 `Design/Atomic/` 中各 Atom 的验收条件为准；正式测试用例待补充。
12. **需求编号与追踪关系：不需要。** 本版本 PRD 不要求建立唯一需求编号或需求追踪矩阵。
## 20. 工程规则说明

根目录 `AGENTS.md` 是供执行本项目工作的 Agent 阅读和遵守的行为准则及禁止红线，不是本项目的产品范围定义，也不限制产品必须实现或不得实现的功能。

因此，本 PRD 中关于以下能力的需求有效，不构成与 `AGENTS.md` 的项目范围冲突：

- 电机底层驱动。
- 电机直接控制。
- 电机闭环控制和 PID。
- 编码器处理。
- GPIO 和限位开关处理。

执行这些需求时，Agent 仍必须遵守 `AGENTS.md` 中的操作约束，包括未经用户明确允许不得修改代码、必须先检查 `Design` 架构设计、禁止实现 `Design/Atomic` 文档所禁止的功能，以及其他安全和流程要求。
