# ATOM-03：SBUS 串口读取与数值转换

- 更新日期：2026-10-17。
- 以用户最新决定为准：只负责串口读取、SBUS 组帧解码、数值转换及公共数据写入。
- 代码文件严格限定为一个私有头文件、一个 cpp、一个公共 Sbus.hpp。

## 接收入口

`marshland::sbus::ReceiveSbus()` 接收设备名、SbusData、停止标志、x、帧长、中点、最小值、最大值和读取超时。

- 函数在当前调用线程内阻塞接收，由调用方自行放到独立线程运行。
- 停止标志类型为 `const std::atomic<bool>&`；调用方置 true 后，接收函数在下一次 poll 返回或数据批次处理后退出，不提供立即 cancel()。
- 默认无数据 poll 等待上限 20 ms，可由参数指定；实际 poll 等待还受最近有效帧的 200 ms 截止期限限制，不能因为传入较大的读取超时而推迟失联检查。
- 正常请求停止返回 true；参数错误、设备打开/配置失败或永久 I/O 错误返回 false。
- 所有返回路径先关闭已打开的串口。若此时仍 online=true，当前调用线程等待最近有效帧的剩余 200 ms 期限到达，再经同一个超时判定清离线后返回；若原本离线则不额外等待。停止/错误不能提前清离线，也不能在接收函数退出后永久留下在线状态。
- 永久设备错误不自动重试或重开，不产生错误空转；没有新增线程，退出等待受调度和外部数据锁影响。

## 串口与组帧

- 设备路径为参数，不固定 UART10；串口格式在代码中固定 100000 baud、8 数据位、偶校验、2 停止位。
- 使用 Linux 原生 termios2、BOTHER 和 ioctl；使用原始模式，关闭软硬件流控，电平反转由硬件完成。
- poll/read 批量读取，有限容量环形缓冲区直接保存半帧，持续消费已经到达的完整帧。
- 帧长使用参数，不硬编码标准帧长；0x0F 为帧头，不校验帧尾，不解析 Byte 23 状态。
- 仅解码 CH1～CH15 的 11-bit 数值，并检查这些通道的传入范围；其中任一路越界时整帧不覆盖公共数组。CH16 不解码、不检查范围、不参与在线判定。
- 任一路被检查的通道越界，直接按完整 frame_bytes 丢弃该候选帧；不改为滑动一字节重试，不刷新有效帧时间，也不因该次拒帧清离线。CH3 异常原因本次不继续调查或放宽校验。
- 单次 poll 等待超时保留未完成帧，不清空环形缓冲；不因无数据等待、同步丢字节或临时读取错误直接改变 online。
- 仍按传入的完整帧长消费字节，不因忽略 CH16 而缩短帧长、截断载荷或更改同步规则。
- 保留最短通道载荷和 minimum<center<maximum 等内存/运算安全检查，不要求固定标定值。

## 数值范围

- 公共数组仍为 16 个元素，下标 0～14 对应 CH1～CH15；下标 15 为已弃用 CH16 的占位槽，每次有效帧发布时固定写 0，不表示 CH16 的原始值或映射值。
- 通用映射：`(raw - center) * x`，x 为 uint8_t，许可范围 1～10。
- 推荐标定 minimum=364、center=1024、maximum=1684，输出 `-660*x`～`+660*x`。
- CH12（下标 11）不使用 x；以 center 为界分别使用负、正量程缩放，minimum/center/maximum 对应 -2000/0/+2000 rpm。
- CH7 为发射输入，保存到 scaled_channels[6]；CH13 为供弹舵机输入，保存到 scaled_channels[12]。两者独立使用同一个通用公式 `(raw-center)*x`，均无持续帧数确认、动作请求或舵机角度/PWM 转换。
- CH14～CH15 保留解析数值，不映射为动作；CH16 直接丢弃。CH5、CH6 的控制权/急停含义由消费方解释，ATOM-03 只保存数值。
- CH2/3/4、CH8～CH12 的机构含义由消费方决定，ATOM-03 不产生机构命令。

## 公共结构体

`SbusData` 只保留 mutex、scaled_channels 和 online。公共头不依赖任何其他 ATOM；原始值仅为接收过程中的局部变量，不公开。

- 调用方提供一份 SbusData，接收函数是唯一写入方；所有读写都持有其 mutex。
- 消费方使用 const SbusData& 并持锁复制字段，不保留内部数组元素引用。
- online 默认初始化为 false；有效整帧在同一次加锁中替换全部映射通道、刷新本调用内部的单调时钟计时，并置 true。
- 除默认初始化之外，运行时唯一 online=false 写入点是失联判定：距最近有效帧已满 200 ms。超时前坏帧、丢字节、临时错误或无数据均不清离线，也不延长在线期限；持续收到坏帧仍会在无有效帧满 200 ms 后离线。
- 接收数据、失联检查和退出等待均不清空上次通道数组；消费者必须在同一把锁内复制数组及 online，不能使用离线旧值作为新输入。
- 此 200 ms 判定在原接收线程使用 steady_clock 执行；不会增加独立看门狗线程，实际检查仍受线程调度、日志调用和外部锁等待影响。online 不表示控制权或执行授权，也不解析无线链路 failsafe 状态。
- 公共结构体不增加时间戳、序号、统计信息、发射确认或业务状态。ReceiveSbus 的签名及 bool 返回含义不变，不用数组内容代替函数错误处理。
- 调用方保证数据及停止标志在接收期间存活，不得持有数据锁等待接收函数结束。

## 明确排除

生命周期管理、配置文件读取、线程创建/注册、仲裁、安全上报、发射授权、自动流程、失联降级、执行器调用及外部调用方迁移均不属于此次实现。

## 接收诊断日志

- 用户授权为 online 始终为 false 的现场问题补充日志；仅通过 Public/Log.hpp 的 marshland::log::Log() 发布，不自行 Init 或改变全局日志阈值。
- 使用 [SBUS] 前缀，启动记录设备、数据对象地址、实际映射/帧长/超时参数；分别记录 open、TCGETS2、TCSETS2、TCFLSH、poll、read 的失败阶段和 errno/revents。
- 首次 UART 读取记录字节数和最多 32 字节十六进制；帧拒绝记录首个越界通道号、原始值及允许范围；失步记录被丢字节，poll 超时记录保留的半帧长度和无有效帧时长。
- 有效帧从离线恢复在线时记录输入样例，退出记录停止标志与返回结果；半帧等待使用 DEBUG，其余关键路径使用 INFO/WARN/ERROR。
- 重复超时、失步、越界拒帧、临时错误、半帧等待和在线恢复分别限为每秒最多一次。所有日志调用均在 SbusData::mutex 解锁后，不增加公共统计字段。
- 只有有效帧超时触发实际在线到离线转换时发布 `online=false: no valid frame ... loss_timeout_ms=200`；普通丢字节、拒帧或读取超时的日志不再宣称它们直接清离线。
- 帧长和 CH1～CH15 范围检查保持不变，CH16 已忽略；本次授权将事件式清离线改为 200 ms 有效帧超时，现场结果仍需目标机确认。
- 接入程序必须链接 Public/Log.hpp 的日志实现；不引入任何日志模块私有头文件，不增加代码文件。
