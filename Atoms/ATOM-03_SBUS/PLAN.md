# ATOM-03_SBUS 初步实现方案

> 状态：初步方案，尚未开始模块代码实现。  
> 日期：2026-09-27  
> 依据：本目录 `AGENTS.md` 与 `Design/Atomic/ATOM-03_SBUS.md`。

## 1. 目标与边界

实现 SBUS 接收、帧有效性校验、通道解析及配置映射，将结果作为普通控制意图、自动模式标志或安全意图提交给相应上层模块。SBUS 适配器不直接驱动电机或舵机，不提供 `main` 入口。

## 2. 初步处理流程

1. **读取配置与依赖确认**：从 Config 获取串口、失联阈值、连续摇杆的中心/有效范围、离散开关有效值及动作映射。动作映射以 Config 7.1 为唯一依据；标记为 `[待定]` 的通道保持未映射，不自行推断。
2. **接收和校验**：从配置指定的串口接收帧，按确认后的 SBUS 帧格式与有效性规则校验。无效帧不产生控制/安全意图，也不刷新最近有效帧时间。
3. **解码和映射**：将有效帧解码为通道值，分别校验连续值和离散值，并按配置形成对应的单一普通动作意图、自动模式标志或安全意图。
4. **提交意图**：普通动作提交 ATOM-02 仲裁；急停与人工确认分别提交 SafetyManager。模块不绕过仲裁或安全管理流程。
5. **失联与恢复**：以单调时钟记录最近有效帧。超过配置阈值后撤销 SBUS 普通控制有效性并停止接受普通 SBUS 命令，使普通控制源降级至 WEB。有效帧恢复后重新依据自动模式标志和 `SBUS > WEB` 规则选择控制源；不得恢复已终止的自动发射流程，也不得自动解除急停锁定。

## 3. 建议的代码组织

- 若采用常规源文件：头文件置于 `Inc/`，实现置于 `Src/`。
- 若最终采用 header-only：头文件直接置于本目录，不创建 `Inc/` 或 `Src/`。
- 将帧解析/校验和通道映射尽量设计为可独立验证的逻辑；串口、时钟、Config、仲裁与安全管理通过已确认的项目接口接入。
- 不在本模块新增进程入口，也不增加直接操纵执行器的路径。

## 4. 验证计划

- 有效帧能按配置产生对应意图；待定通道不会产生臆造映射。
- 无效帧不产生意图且不刷新有效帧时间。
- 连续通道中心/范围及离散开关边界按 Config 校验。
- 达到失联阈值后普通 SBUS 控制失效并降级至 WEB；有效帧恢复后恢复 SBUS 优先规则。
- 自动模式标志、普通动作意图、急停和人工确认走各自规定的提交路径。
- 断连/重连不恢复已终止的自动流程，急停锁定保持有效。

## 5. 实现前需确认的接口与未决项

- `Public` 中 Config、串口、单调时钟、ATOM-02 仲裁及 SafetyManager 的实际类型、调用方式和依赖关系。
- Config 7.1 的完整通道映射；所有 `[待定]` 项在权威配置明确前保持不实现。
- 帧格式/有效性判定的项目约定，以及串口接收的缓冲、并发和生命周期约定。
- 控制意图及安全请求的数据结构和错误处理约定。

上述信息确认后再收敛具体类/函数接口与测试替身；本文件不预设尚未定义的通道或上层 API。
