## 4. 状态与不变量

记每通道状态为 `(enabled, target_active, fault, output, pid_history, next_due)`，公共状态写入均受 `mutex_` 保护。工作线程与手工 `tick()`/`updateOnce()` 使用同一锁及绝对期限。

### I1 配置按 ID 隔离且事务提交

`LoadMotorRuntimeConfig()` 只写局部 `loaded`，任何查询失败、类型/范围错误、版本变化或重复映射均在 `output=loaded` 前返回。映射恰好包含唯一 ID 1～6，且 node=`0x200+id`，role 与 ID 一致。数组顺序不是身份。`configure()` 验证后才替换状态，运行或通知执行中拒绝配置。

因此：`Load 失败 => 调用方 output 不变`；有效配置不会产生重复 CAN 槽位。

### I2 有效反馈不由缺失或异常数据伪造

反馈解析先检查 node、DLC、角度、转速与温度，然后提交局部对象。`has_received` 区分首帧时间戳 0 与未收到。无效帧将已有反馈标为无效并保持待处理故障；后续有效帧不能隐式丢弃该故障。重复/旧帧不刷新时间；未来时间戳拒绝。

反馈使用前必须满足 `valid && has_received && pending_fault==NONE && stamp<=now && now-stamp<timeout`。等于超时阈值即超时。快照返回复制值并重算有效性，旧数值可供诊断，但 `valid=false` 时禁止控制。

### I3 输出有界且未用槽位为零

PID 输出按有效上限 L 钳位，`0<L<=15000`；命令输出经过最终许可、命令限幅与安全限幅。非有限结果在整数转换前锁存故障。转换函数先限制 mA，再计算协议计数；最大中间积 `15000*16384=245760000` 在 `int64` 中，编码范围 ±12288，满足 `int16`。

批次先全零初始化，只有 `enabled && target_active && fault==NONE` 通道能写入唯一槽位。`0x1FF` 未使用的后两个槽位始终为零。输出端的物理发送结果不是本不变量的结论。

### I4 撤销和故障不会由旧 PID 输出恢复

`revokeLocked()` 令 `enabled=false`、`target_active=false`、`output=0`、command=DISABLED，并清 PID 历史及期限；换弹对通过 `revokePairLocked()` 联动。`faultLocked()` 在同一锁内撤销根因与伙伴，故障保持锁存。

对并发“PID 更新/停止”只有两种线性化顺序：更新先获得锁则停止随后清零；停止先获得锁则更新看见非活动状态，不能计算旧目标。外部已经拿到的旧 batch 还需由 A2/A3 拒绝。清故障与重新启用均不恢复旧目标，只有新的授权命令能激活。

### I5 热加载与保存分离

参数校验与 WEB/MANUAL/DEBUG 许可都在活动参数赋值前进行。拒绝请求不修改 PID 且不调用持久化。接受请求在控制锁内设置参数与 revision，活动速度通道立即重新计算；控制或输出故障不会把参数应用事实误报为未应用。

`pid_update_mutex_` 覆盖同一 core 的编辑及保存顺序，但控制锁在文件后端调用前释放；控制线程不执行保存。`SAVED` 只来自后端明确返回，其他异常结果归 FAILED，UNAVAILABLE 保留；保存失败不回滚已生效参数。参数配置、输出成功、文件保存不是同一个结果。

### I6 PID 数值与饱和故障

检查参数有效、dt 有限且 `0<dt<=0.1`，差分、积分候选及原始输出均检查有限性。积分存储的是输出贡献，限幅对负 Ki 同样适用；首次不差分。

饱和计数 c 的转换为：未饱和 `c'=0`；首次或误差改善 `c'=1`；其余 `c'=min(c+1,5)`。由归纳可知 `0<=c<=5`。连续五次达到有效限幅且后续误差不改善时 c=5，返回 PID_SATURATION，输出默认 0，core 撤销通道；改善或未饱和打断原序列。

### I7 通知与故障清除顺序

零电流提交尝试先于 `publishFaults()`。取出事件时标记 in-flight，释放控制锁后调用桥，全部通知完成后才清除标记。`clearFault()` 对两侧先做全部反馈/许可检查再修改，并在待通知或执行中返回 BUSY；因此不会出现清故障后旧通知取消新动作的窗口。

`zero_latched=false` 必须向安全桥暴露，不能伪装已发送零力矩。反馈异常发生在 RX 上时，外部故障通知在工作线程或其他控制调用处理该异常后执行，不在 RX 上回调 CAN。

### I8 幂等停止与锁顺序

`stop()` 先关闭 running 并唤醒，第一次停止在控制锁内撤销全部目标、提交零电流，然后释放控制锁再 join。`stopped_` 防止重复提交。两个适配器均可调用 stop，不产生重复线程。

锁嵌套为 `lifecycle -> pid_update -> control`（configure）、`pid_update -> control`（更新）、`lifecycle -> control`（启动/停止）；等待锁与控制锁不嵌套。工作线程不获取生命周期锁，join 不持有控制锁。外部回调遵守 A6 时，没有上述锁构成的逆序环。
