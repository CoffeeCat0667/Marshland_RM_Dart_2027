# ATOM-02 State Arbitration 实现计划

## 1. 目标与边界

实现系统状态机、自动流程状态、当前控制源选择结果以及实际发射授权仲裁。模块只负责状态与授权决策，不直接发送 CAN/IIC 报文，也不直接执行机构动作；不存在 `main` 入口函数。

## 2. 目录与构建方案

- 头文件统一放入 `Inc/`，源文件统一放入 `Src/`。
- 模块通过本目录的 `CMakeLists.txt` 暴露一个可被上层工程调用的目标 `atom02_state_arbitration`。
- 初始阶段使用 `INTERFACE` 目标承载模块组织、公共头文件路径和后续依赖；当实现文件落地后，将目标切换为实际库目标并保持上层调用名称稳定。
- 编译标准、平台、编译选项由上层 `NewVersion/CMakeLists.txt` 统一控制，本模块不重复设置可执行程序或独立编译链。

## 3. 核心模型

规划以下枚举/数据模型：

- 系统模式：至少覆盖 `STANDBY`、`AUTO`、`WEB`、`DEBUG`、`CALIBRATION` 等设计要求的模式。
- 自动流程状态：区分运行、停止、被 SBUS 接管后终止等状态，确保旧自动流程不能在接管后继续运行。
- 控制源：`AUTO`、`WEB`、`SBUS`，并区分“当前控制源选择结果”和“实际发射授权优先级”。
- 仲裁上下文：WEB/SBUS 在线状态、SBUS 自动模式标志、软件急停、停止发射标志、故障状态、当前模式及时间/序号信息。
- 状态事件/仲裁结果：包含旧状态、新状态、原因、是否允许执行，以及必要的控制源变化信息。

## 4. 行为实现顺序

1. 提供当前系统模式、自动流程状态和当前控制源的查询接口。
2. 对模式切换执行合法性校验；非法切换不改变目标状态，并返回明确原因。
3. 对每次有效状态转换生成包含旧状态、新状态和原因的状态事件。
4. 按规则计算当前控制源：无 WEB 时初始为 `AUTO`；WEB 在线且无更高优先级条件时选择 `WEB`；SBUS 在线时根据自动模式标志选择 `AUTO` 或 `SBUS`；SBUS 失联降级至 `WEB`，恢复有效帧后重新应用 SBUS 规则。
5. 对普通 SBUS/WEB 控制意图执行仲裁；低优先级冲突命令被拒绝且不得修改控制目标。
6. 在每次 `FireAction` 前重新检查 `SBUS > WEB > 自动流程` 的发射授权、停止发射、故障和软件急停条件；任一条件不满足都不得进入发射动作。
7. SBUS 接管自动流程时，允许当前硬件动作组完成后终止原自动流程；不得暂停或恢复旧流程。
8. 软件急停保持最高约束，不能通过普通模式切换解除；调试/校准授权时切换到对应系统模式并记录原因。
9. 记录每次控制源变化及抢占原因，便于上层日志或事件适配器接入。

## 5. 安全与接口约束

- 自动模式为真时可以显示 `AUTO`，但 SBUS/WEB 仍可按规则介入；介入命令必须经过仲裁。
- 控制源选择结果不得改变实际发射授权优先级。
- 状态机只输出状态、授权和事件结果，不直接访问硬件驱动。
- 所有对外接口尽量保持无副作用；提交状态变化与执行授权时使用明确的结果类型，避免调用方误把拒绝当成成功。

## 6. 验证计划

- 覆盖初始控制源、WEB 上线/下线、SBUS 自动/手动、SBUS 失联与恢复等选择规则。
- 覆盖状态切换合法性、非法切换不修改状态、事件内容完整性。
- 覆盖 `SBUS > WEB > AUTO` 的冲突仲裁与低优先级拒绝行为。
- 覆盖急停、停止发射、故障、未授权时禁止 `FireAction`。
- 覆盖 SBUS 接管后自动流程终止、旧流程不可继续运行。
- 使用上层 ARM 构建链进行编译验证；本模块不创建测试入口 `main`。

## 7. 待实现文件建议

- `Inc/StateArbitration.hpp`：公共枚举、上下文、结果、事件和类接口。
- `Src/StateArbitration.cpp`：状态转换、控制源选择、授权仲裁及事件生成实现。
- 如最终实现采用纯头文件形式，可按规则取消 `Inc/` 与 `Src/`，并同步调整本模块 CMake 配置。
