## 1. 各项细节

### BUG-20261015-16-01 — http 配置节整体缺失（致命）

**现象**：`Config/dart_control.json`（339 行，全文已读）顶层只有 `schema_version, baseline, mode, timing, motor, charge, force, can, sbus, servo, thread, persistence, reserved_001`——**无 `http` 节**。schema.json 中 `http` 是合法但非必需的顶层域（根 `required` 不含 `http`，`additionalProperties: false` 允许补入）。

**影响**：ATOM-16 的 `initialize()` 按 fail-closed 设计读取 `http.listen_address` / `http.port` / `http.request_body_limit_bytes` / `http.response_body_limit_bytes` / `http.request_timeout_ms`——全部 MISSING 即初始化失败（不猜默认值，遵循 `IConfigView`「禁止返回默认值+无提示掩盖错误」与 Config.md §17.8）。

**处置**：由用户把 §3 的 http 节草稿补入 `dart_control.json`。

### BUG-20261015-16-02 — Rule 文档与 schema 键名不一致

**现象**：`Rule/ConfigSchema.md:621` 写 `http.status_mapping`；`Rule/ConfigSchema.schema.json:726` 实际定义 `http.http_status_mapping`。ConfigSchema.md 自述"两者不一致时以 schema 文件为准"。

**影响**：ATOM-16 的 `Inc/ConfigKeys.hpp` 目前沿用了文档名，需修正为 `http.http_status_mapping`。

**处置**：Rule 文档维护方修订 ConfigSchema.md；ATOM-16 随后改键常量（一行）。

### BUG-20261015-16-03 — IConfigView 嵌套数组查询未落地

**现象**：`Atoms/Public/IConfigView.hpp:101-130` 已新增 `getNestedArraySize` / `getNestedStringAt`（默认实现返回 MISSING，注释说明背景是 `websocket.message_types[].payload_fields` 类结构）；但 `Atoms/ATOM-15_Config_Persistence/Inc/atom15_config/config_store.hpp:38-49` 的 override 列表**不含**这两个方法，`config_store.cpp` 无实现。

**影响**：`http.manual_actions[].allowed_modes`（元素内嵌套数组）读不出；动作白名单的"允许模式"列过渡期只能按 Config.md §11.4 硬编码。其余字段（`action`/`requires_target`/`target_unit`）可经现有 `getArraySize` + `getStringAt`/`getBoolAt` 读取。

**处置**：ATOM-15 实现两个 nested override 后，ATOM-16 改回全量配置驱动。

### BUG-20261015-16-04 / 05 / 06 — ATOM-12 / 13 / 19 未实现

**现象**：三个目录均只有 `AGENTS.md` + `CMakeLists.txt`（INTERFACE 占位）+ `PLAN.md`，无 `Inc/`、`Src/`。

**影响**：`yaw_set`（YAW 目标 rpm）、`auto_start`/`auto_stop` 的执行侧（PEFExecutor）、`/api/calibration`（校准分派）**无通道**。注意与 BUG-07 的区别：这不是"接口私有待桥接"，而是**代码不存在**。

**ATOM-16 侧过渡行为**：相关路由/action 返回 `DEPENDENCY_UNAVAILABLE`（503），不谎报成功；通道出现后薄适配替换。

### BUG-20261015-16-07 — 装配层注册与窄接口桥接待办

**现象**：`Entry.cpp:576-577` 有占位注释（"Remaining lifecycle adapters (ATOM-06, 12..14, 16..19) are registered here…"）。ATOM-16 的接入要素已明确：

- 构造时机：必须在 `AppCoordinator app`（`Entry.cpp:461`）**之后**（Dependencies 需要 `app` 提供的 `IStateReader`/`IControlAuthority`/`IInputReporter`）；
- 注入：`{&config_store, &clock, &app, &app, &app}` + 诊断三件套（`IDiagnosticsSnapshotProvider`/`IFaultRegistry`/`ILogSink`，见 ATOM-18 ConnectProject §6 的 http_adapter 注入示例）；
- 注册步骤：`RuntimeStep::StartHttpAndWebSocket`；`required` 取值需顶层裁决（参考 ATOM-03 用 `false` 的先例）；
- **窄接口桥接（2026-10-15 用户裁决：方案"装配层窄接口"）**：ATOM-16 在自有 `Inc/` 定义窄接口（蓄力/换弹供弹/发射/舵机/急停确认/参数写入各一个），装配层在 Entry.cpp 写适配器转发到 `atom08::ChargeController` / `atom10::ReloadFeedCore` / `atom11::LifecycleAdapter` / `atom07::ServoCore` / `safety::SafetyRecovery::onEstopConfirmRequest()` / `atom15::ConfigStore::updateRuntime|writePid`——与 Entry.cpp 既有 Stub/桥接模式一致；**ATOM-16 不包含任何模块私有头**。

**处置**：ATOM-16 先交付窄接口定义与消费侧实现；装配层侧接线由用户/装配方完成。

### BUG-20261015-16-08 — auto/stop 文档冲突（已裁决，待文档同步）

**冲突原文**（2026-10-15 重读确认仍为最新版原文）：

- `Design/Config.md:476`（v1.4）：`应急链路；无急停、活动故障或更高优先级控制接管时可用`
- `Design/Interface.md:680`（v1.8）：`始终可用`（且与 Interface.md:689 的"应急链路"表述自相矛盾）

**裁决（2026-10-15，用户）**：**始终可用**。佐证：`StateArbitrationTypes.hpp` 中 `IntentKind::STOP_FIRE_SET` 注释"安全单调：只收紧，不受优先级阻断"。

**待办**：`Design/Config.md:476`（及 :485、:502 两处链路分工注释）需修订为"始终可用"以消除冲突；ATOM-16 按裁决实现。

### BUG-20261015-16-09 — ATOM-16 规划文档基线过期

### BUG-20261015-16-11 — web_online 归属与 ATOM-17 注册

**裁决（2026-10-15，用户）**：**ATOM-16 不上报 `web_online`**；该标志由 ATOM-17（WebSocket 长连接 + 心跳，`websocket.heartbeat_period_ms`）唯一上报。

**推论**：仅发起 HTTP 请求而未建立 WS 的客户端不会使控制源切换为 WEB；ATOM-17 未注册进 Entry.cpp 前，`web_online` 恒为 false。
