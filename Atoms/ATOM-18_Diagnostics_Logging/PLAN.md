# ATOM-18 Diagnostics & Logging 实现计划

## 1. 目标与边界

实现 Marshland 的诊断与日志模块，为故障、状态变化及关键流程提供可查询的结构化记录，并按 `Config` 输出日志。模块只负责记录、查询、状态维护、轮转与诊断快照，不负责自行决定机构控制命令。

约束：

- 不提供 `main` 入口函数。
- 头文件放在 `Inc/`，源文件放在 `Src/`。
- 编译标准、目标平台和编译选项由上层 CMake 工程统一决定；本目录只负责模块组织、依赖和配置。
- 时间戳使用 UTC；轮转阈值使用单调时钟。
- 日志采用 JSON Lines 格式，配置项从 `Config` 读取。

## 2. 初步模块划分

### 2.1 公共模型与接口

- `LogLevel`：日志等级。
- `LogEvent`：时间戳、等级、模块、事件、来源、状态和 payload。
- `FaultRecord`：故障码、等级、发生时间、来源、活动/历史状态及恢复状态。
- 诊断日志、运行日志、安全日志的写入接口。
- 活动故障、历史故障、状态迁移、控制权变更、发射结果、急停/人工解除和诊断快照接口。

### 2.2 故障管理

- 按故障码、来源和发生时间查询故障。
- 区分活动故障与历史故障。
- 单独更新故障恢复状态，清除满足策略的单条故障，不误清除其他故障。
- 保存故障发生时间和来源。

### 2.3 日志写入与轮转

- 结构化序列化为 JSON Lines。
- 普通日志按配置策略刷新。
- `ERROR` 和安全事件立即刷新。
- 轮转阈值达到后执行一次文件轮转。
- 超过总存储上限时删除最旧的单个日志文件。
- 轮转、清理和刷新不能阻塞控制线程；具体实现需采用非阻塞/异步队列或等价隔离策略。

### 2.4 诊断规则

- 记录 30 秒回退后的迟到视觉状态。
- 当前发次尚未实际发射时，记录重新执行 YAW 到位检查的事件。
- 当前发次已经完成发射时，记录迟到视觉状态事件，不回滚已完成动作。

## 4. CMake 集成方案

- 本目录定义一个不生成独立可执行文件的模块库目标 `atom18_diagnostics_logging`。
- 使用 `INTERFACE` 目标承载公共头文件路径、模块编译定义和未来依赖，避免本模块独立编译。
- 提供 `Marshland::ATOM18_Diagnostics_Logging` 别名，便于上层工程链接。
- `Inc/` 和 `Src/` 仅作为本模块组织约定；具体源文件由后续实现阶段加入，编译选项继续继承上层工程设置。
- 不在本目录引入 `project()`、`main()` 或独立工具链设置。

## 5. 实施顺序

1. 确认 `Config` 的日志配置访问接口及 `Public` 中可复用的公共类型/错误码。
2. 定义稳定的公共数据模型和线程安全接口。
3. 实现 JSON Lines 序列化及 UTC 时间戳生成。
4. 实现故障记录、活动/历史查询、恢复状态和单条清除。
5. 实现日志队列、刷新策略、立即刷新规则和文件轮转/容量清理。
6. 实现状态迁移、控制权、发射结果、急停/人工解除等专用记录接口。
7. 实现诊断快照及 30 秒回退视觉状态规则。
8. 增加单元测试与边界测试，覆盖查询隔离、轮转清理、刷新策略、并发访问和“不回滚已完成动作”。
9. 由上层 CMake 在允许的 ARM 构建环境中完成集成验证。

## 6. 验收映射

- 每个故障事件可按故障码、来源和时间查询。
- 活动故障与历史故障清晰区分；清除单条故障不影响其他故障。
- 状态迁移、控制权变更、发射结果、急停和恢复均生成结构化日志。
- 达到单文件或总容量限制时按配置轮转/清理，且不阻塞控制线程。
- 安全事件和 `ERROR` 立即刷新，普通日志遵循配置策略。
- 诊断规则能够区分“尚未实际发射”和“已完成发射”两种情况。
