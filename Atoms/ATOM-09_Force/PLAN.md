# ATOM-09 Force 实现方案

## 1. 目标与边界

实现 `ATOM-09_Force` 变力机构控制原子：接收一个经过授权和范围校验的变力目标，使用 Config 中的映射关系（当前电机 ID 为 4）驱动对应电机闭环执行，接收电机反馈并维护目标、当前反馈、动作状态及错误状态。

本模块不负责发射流程编排，不实现 `main`，也不自行定义专属故障恢复策略；通用电机、PID、编码器和 CAN 故障按既有通用故障表并转交 ATOM-14。

## 2. 当前已知约束与待确认接口

- C++ 标准、目标平台、编译选项由上层 `NewVersion/CMakeLists.txt` 统一决定。
- 本目录的 CMake 只负责模块化组织、目标声明和模块依赖，不独立设置编译链或创建可执行程序。
- 需要在实现前确认/对接以下既有接口，避免在 ATOM-09 内重复定义：
  - Config：变力模式、目标范围、电机映射、动作持续时间 X 秒及相关授权配置。
  - ATOM-05：按电机 ID 提交目标、闭环/PID 执行以及反馈获取接口。
  - ATOM-14：通用故障报告接口和故障数据结构。
  - 电机反馈、PID、CAN 故障码及时间源接口。
- 在上述接口信息不足时，先补充接口调查或请求确认，不直接臆造公共 API。

## 3. 建议目录与组件

```text
ATOM-09_Force/
├── CMakeLists.txt
├── PLAN.md
├── Inc/
│   └── ForceController.hpp       # 对外接口、类型、状态和错误定义
└── Src/
    └── ForceController.cpp      # 校验、提交、反馈更新、计时和故障转发
```

建议以 `ForceController` 作为模块唯一业务入口；依赖通过构造函数注入或明确的适配接口提供，便于测试和替换底层 ATOM-05、Config、时钟及 ATOM-14 服务。

## 4. 核心数据与状态设计

1. **目标类型**：包含变力模式、目标值及必要授权/来源信息；目标值和模式采用明确的强类型表示。
2. **配置快照**：读取并缓存本次动作所需的电机 ID、有效目标范围和持续时间 X；运行中不使用硬编码替代 Config。
3. **反馈状态**：保存最近一条有效电机反馈，以及反馈有效性和最近错误信息。
4. **动作状态**：至少区分 `Idle`、`Running`、`Completed`、`Rejected`/错误状态；动作开始时间和截止时间由注入时钟计算。
5. **错误状态**：区分目标校验失败、配置无效、底层提交失败、反馈故障和通用硬件故障，便于上层查询与 ATOM-14 报告。

## 5. 主要流程

### 5.1 提交变力目标

1. 校验目标类型、模式、授权信息及 Config 范围。
2. 校验 Config 中的电机映射和动作时长有效。
3. 任一校验失败时返回明确错误，且不得改变当前有效目标或运行中的有效状态。
4. 校验成功后，将目标提交给 Config 映射的电机（当前为 ID 4），由 ATOM-05 执行闭环/PID。
5. 记录本次动作目标、开始时间和截止时间，状态置为 `Running`。

### 5.2 反馈与完成判定

1. 接收一条来自映射电机的反馈。
2. 只接受目标电机的反馈，更新当前反馈和底层错误信息。
3. 若出现电机、PID、编码器或 CAN 故障，保留故障信息并调用 ATOM-14 通用故障报告接口。
4. 只有当前时间达到配置的 X 秒截止时间后，才将动作置为 `Completed`。
5. X 秒到期前，即使反馈达到目标，也不能报告变力动作完成。
6. 完成判定应通过显式的 `update/tick` 或等价接口执行，避免隐式线程和额外调度职责。

## 6. 对外能力

提供查询目标、最近反馈、动作状态和错误的只读接口；提供提交目标、接收反馈及推进时间状态的接口。接口返回值应明确表示拒绝、正在执行、完成和故障等结果。

## 7. 验收与测试计划

- 有效目标能够提交到 Config 映射电机，且不影响其他电机。
- 无效类型、模式、授权或越界目标被拒绝，并保持原有效目标不变。
- 提交失败时不误报动作已开始或已完成。
- X 秒前始终不是完成状态；到期后恰好转为完成状态。
- 非映射电机反馈不会覆盖当前变力反馈。
- 电机/PID/编码器/CAN 故障被保留并报告给 ATOM-14。
- 每次外部流程触发只产生一次变力动作；本模块不自行安排第 1 至第 4 发顺序。
- 使用可注入时钟和底层适配器进行边界测试，重点覆盖零时长、过期时间、重复提交、反馈乱序和配置无效场景。

## 8. 实施顺序

1. 根据允许读取的设计资料和现有公共接口确认 Config、ATOM-05、ATOM-14 的实际 API。
2. 完善 `Inc/` 中的领域类型、依赖抽象和 `ForceController` 对外接口。
3. 在 `Src/` 实现校验、目标提交、反馈更新、计时完成和故障转发。
4. 更新本目录 CMake 的源文件、头文件、依赖目标和 include 路径；不改动上层 CMake。
5. 在符合目标 ARM 架构的上层构建环境中编译并执行模块级测试/集成验证。
6. 对照验收条件复核，特别确认无 `main`、无硬编码配置替代和无额外流程编排。
