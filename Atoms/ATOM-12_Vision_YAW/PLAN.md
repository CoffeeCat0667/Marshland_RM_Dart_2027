# ATOM-12 Vision YAW 实现方案（初稿）

## 1. 模块目标

实现视觉系统到 YAW 控制链路的原子模块：接收并校验视觉 YAW rpm 目标与视觉 YAW 到位状态，向 YAW 电机闭环控制链路提交自动目标，并向自动流程提供当前发次的到位状态与诊断结果。

本模块不实现进程入口，不包含 `main`，不直接拥有发射授权，也不直接写入视觉系统拥有的正常到位输入。

## 2. 已确认的关键规则

- YAW 目标单位为 rpm，映射到 Config 定义的 YAW 电机，当前电机 ID 为 3。
- 通过 ATOM-05/ATOM-04 的 CAN 闭环链路驱动 YAW 电机。
- YAW 电机自身调整超过 2000 ms 时，不立即终止当前发次，继续等待视觉系统；视觉链路无有效响应持续 30 s 后才进入控制主系统规定的回退到位处理。
- 视觉状态更新超过 200 ms 或链路中断时，撤销旧到位授权并报告 `F-VISION-001`。
- 视觉链路在 30 s 内恢复时，清除该故障、恢复通信、重新请求当前发次的到位状态，并重新开始 30 s 计时；不触发一般故障恢复流程。
- 正常视觉到位和 30 s 超时回退到位均必须经过发射前停止标志、控制源优先级、故障和急停检查。
- 新发次开始前必须清除上一发次的到位状态；发射完成后由主控清除视觉到位 bool。
- 手动 YAW 目标遵循 ATOM-02 仲裁规则，并与自动视觉 YAW 目标互斥。
- 当前发次已实际发射完成后，视觉状态变化不得回滚已完成动作，只记录诊断事件。

## 3. 建议的模块边界

### 对外接口（计划放入 `Inc/`）

- `VisionYawController`：模块状态机、发次生命周期与输入校验。
- 视觉输入模型：YAW rpm、视觉到位 bool、时间戳/链路有效性、发次标识。
- 输出模型：YAW 电机目标、到位事件、故障/诊断事件、回退请求和状态快照。
- 依赖端口：Config 电机映射、ATOM-05/ATOM-04 控制适配器、PEFExecutor/主控制系统事件接口。

接口设计应尽量使用抽象端口或回调，不在本 Atom 内绑定具体 CAN 驱动实现，便于由上层工程装配。

### 内部实现（计划放入 `Src/`）

- 发次状态机：Idle、Tracking、AwaitingAlignment、Aligned、VisionTimeoutFallback、Completed/Aborted 等状态。
- 视觉更新时间监视：200 ms 更新超时检测与 30 s 无响应回退计时。
- 2000 ms 电机调整窗口处理：只更新等待/诊断状态，不提前触发发射禁止。
- 到位判定与安全门检查：正常视觉到位、超时回退到位均复用统一安全检查。
- 发次隔离与幂等处理：防止复用上一发次状态，保证已完成发射不可回滚。
- 手动/自动目标仲裁：按 ATOM-02 优先级拒绝冲突目标。

## 4. 状态与时序设计

1. `beginCycle()` 开始新发次，清除旧视觉到位状态，初始化当前发次 ID 与计时器。
2. 接收视觉 YAW rpm 后校验来源、发次 ID、数值范围和时间戳，再提交到 YAW 电机控制端口。
3. 接收视觉到位 bool；只有当前发次、链路有效且安全门允许时，才生成视觉到位事件。
4. 每次周期调用 `tick(now)`：检查 200 ms 视觉更新超时、30 s 无响应超时及电机 2000 ms 调整状态。
5. 视觉到位为真时执行统一安全检查并通知 PEFExecutor；成功发射后等待主控清除视觉 bool。
6. 视觉断链/超时先撤销旧授权并报告 `F-VISION-001`；30 s 到期后请求主控执行回退到位。
7. 视觉恢复时清除故障并重新进入当前发次等待流程；若当前发次已完成发射，只追加诊断，不回滚。
8. `endCycle()` 或主控清理事件释放本发次所有状态，防止泄漏到下一发次。

## 5. CMake 组织方案

- 本目录提供 `atom12_vision_yaw` 模块目标，并提供 `ATOM12::VisionYaw` 别名。
- 当前目录尚无实现源码，因此先以 `INTERFACE` 目标完成模块化占位；加入 `Inc/` 和 `Src/` 后，切换为静态库目标并由本目录 CMake 管理源文件。
- 不设置编译器、架构或构建类型；这些由上层 `NewVersion/CMakeLists.txt` 统一决定。
- 不在本目录创建可执行文件，不添加 `main`。
