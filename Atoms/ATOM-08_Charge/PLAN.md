# ATOM-08_Charge 初步实现方案

## 1. 目标与边界

本模块实现 ATOM-08“蓄力机构控制”，负责蓄力机构电机 1、2 的正常恒速蓄力、普通停止、限位回零、状态维护及错误上报接口。模块不包含 `main` 入口，不负责进程启动、全局调度或其他原子功能。

依据功能规划（ATOM-08，基线 2026-09-26），模块需要覆盖：

- 普通蓄力命令的运行模式、控制权和安全条件校验；
- 向电机 1、2 分别提交配置的恒定速度目标；
- 从蓄力启动时刻开始计时，X 秒到期后结束正常蓄力并标记完成；
- 普通停止时停止两个电机的正常蓄力目标；
- 分别向电机 1、2 提交回零目标；
- 读取并判定两个限位开关的稳定状态；
- 仅在两个限位同时为低电平时停止回零并标记回零完成；
- 提供状态、目标、完成状态和最近错误查询；
- 将蓄力超时、电机错误和限位错误报告给 ATOM-14。

## 2. 初步模块分层

### 2.1 领域接口与数据模型（`Inc/`）

计划定义以下稳定接口，具体命名可在读取公共接口定义后调整：

- `ChargeController`：蓄力控制器主类，负责命令处理和状态机推进；
- `IChargeMotor`：蓄力电机目标提交、停止和错误读取抽象；
- `ILimitSwitch`：限位开关稳定电平读取抽象；
- `IChargeConfig`：读取蓄力时间 X、蓄力速度和最大动作时间等配置；
- `IChargeSafety`：初始化状态、急停锁定、控制授权和运行模式校验；
- `IChargeFaultReporter`：向 ATOM-14 报告超时、电机和限位错误；
- 命令、状态、目标、错误和完成状态的枚举/结构体。

接口采用依赖注入，使本模块不绑定具体电机驱动、GPIO、配置存储或通信实现，并便于上层集成和测试。

### 2.2 状态机实现（`Src/`）

建议至少划分以下状态：

- `Uninitialized`：未完成初始化；
- `Idle`：空闲，可接受正常蓄力或回零请求；
- `Charging`：两个电机执行正常恒速蓄力并累计 X 秒；
- `ChargeCompleted`：正常蓄力 X 秒完成；
- `Returning`：两个电机执行回零目标；
- `ReturnCompleted`：两个限位均稳定为低电平，回零完成；
- `Stopped` / `Fault`：停止或故障状态，保留最近错误。

状态机应保证：

1. 初始化失败、急停锁定或授权/模式校验失败时，拒绝普通蓄力启动；
2. X 秒未到期时，不得报告正常蓄力完成；
3. 回零只有在两个限位同时为低电平时才能完成；
4. 回零请求必须明确作用于电机 1 和电机 2；
5. 普通停止只停止正常蓄力目标，不将其误判为回零完成；
6. 错误发生时停止相关动作、保留错误信息并通知 ATOM-14。

### 2.3 时间与轮询模型

控制器不自行创建线程。由上层周期性调用 `update(now)`（或等价接口）推进计时和限位判定：

- 启动正常蓄力时记录单调时钟起点；
- 每次更新检查 X 秒完成条件和最大动作时间；
- 回零阶段每次更新读取两个稳定限位状态；
- 时间源通过接口或时间参数注入，避免依赖平台时钟实现。

## 3. CMake 组织方案

本目录已初始化为可被上层调用的模块工程：

- 目标名：`atom08_charge`；
- 当前使用 `INTERFACE` 目标，便于在实现源文件尚未加入前被上层工程安全引用；
- 暴露 `Inc` 作为公共头文件目录；
- 保持 C++ 标准、编译器选项和目标平台约束由上层 CMake 决定；
- 后续出现 `.cpp` 实现后，将目标切换为或扩展为静态库，并通过 `target_sources` 管理 `Src/` 文件；
- 不在本模块 CMake 中新增可执行文件，不定义 `main`，不覆盖上层编译选项。
