# ATOM-16 HTTP/Web 实现方案（初版）

## 1. 目标与边界

实现 ATOM-16 的 HTTP 服务与 Web 前端交互模块：监听 Config 指定的地址和端口，提供静态资源与 JSON API，将请求路由到对应 Atom/服务，并统一生成 Config 约定的成功和错误响应。

本模块不直接操作硬件，不包含 `main` 入口；硬件控制、状态聚合、安全仲裁和配置持久化通过既有接口/依赖完成。

## 2. 计划的模块结构

- `Inc/`：对外头文件。
  - HTTP/Web 服务生命周期接口
  - 路由与请求/响应数据结构
  - 配置、错误和分发接口的抽象定义
- `Src/`：实现文件。
  - HTTP 监听与连接处理
  - 静态资源处理
  - 请求体大小限制和 JSON 解析
  - API 路由、action 白名单与参数校验
  - 结果/错误 JSON 序列化
  - 长流程 accepted + request_id 响应
- `CMakeLists.txt`：提供可被上层工程调用的模块目标，不创建独立可执行程序。

具体 HTTP 库、JSON 库以及 ATOM-02/13/14/15/18/19 和状态聚合器的实际接口，待读取对应公共接口后再落地，避免在本模块重复定义或越权实现。

## 3. 功能实现顺序

1. 定义稳定的请求、响应、路由、配置和分发抽象。
2. 实现监听、静态资源和统一 HTTP 错误处理。
3. 实现 JSON 请求解析、请求体上限检查和统一错误响应。
4. 实现只允许 Config 11.4 action 集合的 `/api/control/manual` 路由。
5. 接入状态查询、诊断、自动启动/停止、`stop_fire`、参数/PID、校准等请求分发。
6. 实现状态/结果 JSON 序列化及长流程异步受理。
7. 接入安全状态机、ControlArbiter 和 SafetyManager，确保优先级为 `SBUS > WEB > 自动流程`。
8. 补充静态前端所需的状态展示、控制提交、结果反馈和受限 PID 编辑能力。

## 4. 必须落实的安全约束

- 所有控制请求均经过状态机、ControlArbiter 和 SafetyManager。
- 急停、故障、模式冲突或高优先级抢占时拒绝普通 WEB 请求，并按 PEF 规则结束相关流程。
- WEB 断线不得启动、恢复或继续已终止的自动流程。
- 急停期间拒绝全部发射舵机普通命令。
- 静态资源请求不触发机构动作。
- `stop_fire_clear` 仅在手动/调试模式执行，执行前必须退出自动模式；清除标志但不恢复或继续自动流程。
- `yaw_set`、`servo_set`、PID 更新严格执行 Config 规定的模式、来源、权限和安全校验。
- 未注册模式切换路由返回错误，不新增独立模式路由。

## 5. 验证方案

- 编译验证：由上层 CMake 在允许的 Ubuntu ARM/aarch64 环境中完成；本模块不配置独立架构和入口。
- 单元测试：请求体上限、JSON 解析错误、action 白名单、路由分发、模式/安全拒绝、响应序列化、request_id。
- 集成测试：监听地址/端口、静态资源、状态/诊断查询、手动控制、自动流程受理、断线与急停行为。
- 安全回归：验证 WEB 不越过仲裁器直接触发硬件，验证 SBUS 优先级和软件急停人工确认约束。
