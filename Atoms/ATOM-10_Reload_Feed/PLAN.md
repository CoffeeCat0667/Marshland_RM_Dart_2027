# ATOM-10 Reload Feed 工作计划（更新版）

## 1. 适用范围与规则边界

本计划依据 ATOM-10 规划文档同步基线 **2026-10-10** 编写。

本工作目录遵循当前 `AGENTS.md`：整个工程仅承担网关和模块组装职责，禁止在本工程中实现 `Design/Atomic` 文档描述的原子功能。因此，本目录后续只能进行以下类型的工作：

- 组织 ATOM-10 的模块目标和依赖；
- 定义或适配网关层所需的接口连接；
- 将已经由其他职责范围提供的 ATOM-04、ATOM-05、ATOM-07、ATOM-14、PEFExecutor、Config 等能力接入上层组装；
- 提供编译配置、依赖声明和接口一致性检查。

不得在本目录实现换弹控制状态机、双 M3508 速度闭环动作、供弹舵机时序、CAN/IIC 驱动、PID 算法或其他 ATOM-10 原子功能。

## 2. 设计文档要点（仅作为组装接口依据）

ATOM-10 的职责边界已从旧版“四舵机换弹”调整为：

- 协调同一换弹机构左右两个 M3508 的速度闭环动作；
- 维护独立的单舵机供弹动作；
- 换弹电机能力由 ATOM-05/ATOM-04 提供；
- 供弹舵机能力由 ATOM-07 提供；
- 本 Atom 不直接实现 CAN/IIC 驱动、PID 算法，不判断已供弹或卡弹。

关键组装约束如下：

- 抬起目标：左电机 `+2000 rpm`，右电机 `-2000 rpm`；
- 放下目标：左电机 `-2000 rpm`，右电机 `+2000 rpm`；
- 抬起/放下均按 Config 规定运行 **3 s**，随后提交左右两侧 `0 rpm`；
- 正常到位保持速度 PID 的 `0 rpm` 闭环；
- 手动停止、急停或单侧故障使用两侧零力矩，不能冒充正常到位；
- 初始化只建立逻辑默认抬起状态和左右两侧 `0 rpm` 目标，不主动抬起、回零、校准或读取换弹限位；
- 供弹时序保持：角度一 → 角度二 → 保持 **100 ms** → 角度一；
- 供弹流程的 **2 s** 计时起点为供弹动作触发时刻；
- 任何电机命令提交失败都必须联动两侧零力矩并报告换弹失败；
- 供弹舵机 IIC 写入失败时不得报告供弹完成；
- 已取消、已失败动作的迟到完成事件必须被拒绝；
- 恢复抬起再次失败时交由 ATOM-14 进入 FAULT 锁定，不自动循环重试。

以上内容只用于检查接口是否能被正确组装，不授权在本目录复制实现这些原子功能。

## 4. 组装接口方案

### 4.1 换弹电机依赖

网关组装层只应依赖已有电机/控制接口，完成以下连接关系：

- Config 5.6：提供左右电机映射、节点/ID、速度目标和运行时间；
- ATOM-04/ATOM-05：提供速度目标提交、状态/反馈检查、零转速闭环和零力矩请求；
- ATOM-14：接收恢复抬起失败后的 FAULT 锁定请求；
- 控制权、安全条件、急停、手动停止和单侧故障状态：由既有上层控制链提供或转发。

本目录不得自行创建 CAN、编码器、PID 或电机底层控制实现。

### 4.2 供弹舵机依赖

网关组装层只应连接 ATOM-07 提供的供弹舵机能力，并传递 Config 中的：

- 舵机编号和通道；
- 角度一、角度二；
- 100 ms 保持参数；
- 供弹写入结果和失败状态。

本目录不得直接访问 IIC 外设，也不得复制供弹动作状态机。

### 4.3 PEFExecutor 协作

仅保留 PEFExecutor 的依赖连接和事件转发约定：

- 供弹触发时记录/传递触发事件；
- 由 PEFExecutor 独立负责从触发时刻起算 2 s；
- 2 s 到期后请求换弹放下；
- ATOM-10 组装层不重新实现 PEFExecutor 的等待计时。

## 5. CMake 方案

当前 `CMakeLists.txt` 保持模块化目标 `atom10_reload_feed`，不创建可执行文件，不设置独立工具链，也不引入 x86 编译链。

后续若需要添加组装适配代码：

1. 将新增源文件放入 `Src/`；
2. 将对外声明放入 `Inc/`；
3. 将目标从当前无源文件的接口目标调整为同名库目标；
4. 仅声明 ATOM-04、ATOM-05、ATOM-07、ATOM-14、PEFExecutor 和 Config 的既有依赖；
5. 不在本模块覆盖上层编译选项；
6. 不创建单独可执行目标；
7. 代码变更后的验证必须使用 ARM 目标环境或 WSL ARM 交叉编译，并且只能增量编译，禁止全量重编译。
