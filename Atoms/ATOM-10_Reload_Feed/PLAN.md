# ATOM-10 Reload Feed 实现方案（初稿）

## 1. 目标与职责边界

实现换弹四舵机动作组与单舵机供弹动作：分别处理舵机写入、动作等待和完成状态。模块只负责动作执行，不判断是否成功供弹、不判断卡弹，也不提供 `main` 入口。

依据规划文件（2026-09-26 同步基线）：
- 换弹抬起：读取四个抬起目标角，依次向 1~4 号舵机各写入一次；命令发送完成后启动配置的 500 ms 判定计时，计时到期标记抬起到位。
- 换弹放下：读取四个放下目标角，依次向 1~4 号舵机各写入一次；命令发送完成后启动配置的 500 ms 判定计时，计时到期标记放下到位。
- 供弹：按角度一（待机）→角度二（换弹位）→保持 100 ms→角度一执行；动作完成后再标记完成。
- 供弹流程的 2 s 计时起点必须是供弹动作触发时刻；PEFExecutor 独立等待这 2 s 后请求换弹放下。
- 任一 IIC 写入失败时，动作不得报告为正常完成。

## 2. 初步模块结构

```text
ATOM-10_Reload_Feed/
├─ CMakeLists.txt
├─ PLAN.md
├─ Inc/
│  └─ Atom10ReloadFeed.hpp       # 对外接口、状态及依赖抽象
```

本轮只初始化目录和模块 CMake；具体接口与源代码待依赖接口（舵机/IIC、时钟/定时器、Config、PEFExecutor）确认后实现，避免在缺少上层接口定义时虚构类型或协议。

## 3. 建议接口与内部设计

### 3.1 外部依赖抽象

- 舵机写入接口：按舵机编号/通道写入目标角，并返回成功或失败。
- 单调时钟或可注入计时器：支持动作触发时刻、500 ms 判定、100 ms 保持和 2 s 流程等待。
- Config：提供四个换弹舵机编号/通道/抬起角/放下角，以及供弹舵机编号/通道/角度一/角度二和延时配置。
- PEFExecutor 协作接口：接收供弹触发事件，并独立在触发时刻起算 2 s 后请求换弹放下。

依赖应通过构造函数注入，便于单元测试、避免模块直接绑定具体硬件实现。

### 3.2 状态机

换弹动作至少区分：空闲、抬起等待、抬起到位、放下等待、放下到位、故障。供弹动作至少区分：空闲、已写入角度二、保持等待、回写角度一等待、完成、故障。新的动作触发、重复触发和故障恢复策略需要结合上层调用约定确定。

### 3.3 错误处理

四个换弹舵机或供弹舵机的任一次 IIC 写入失败，都应立即进入故障/未完成结果；不得仅依靠延时结束来报告成功。动作组写入顺序固定为舵机 1→2→3→4，除非上层接口明确要求事务回滚（当前规划未要求回滚）。

## 4. CMake 初步方案

- 本目录提供 `atom10_reload_feed` 模块目标，并导出 `Inc` 为公开头文件目录。
- 编译标准、平台、警告和工具链完全继承上层 CMake，不在本模块重新指定。
- 当前没有实现源文件，因此先使用可被上层链接的 `INTERFACE` 目标完成模块化接入；开始添加 `.cpp` 实现时，将目标切换为包含 `Src/*.cpp` 的实际库目标，并保留同名目标和公开 include 路径。
- 不创建可执行文件，不定义 `main`。

## 5. 实现步骤

1. 根据上层公共接口确认舵机 IIC 写入、时间服务、Config 和 PEFExecutor 的真实类型与错误模型。
2. 在 `Inc/Atom10ReloadFeed.hpp` 定义最小公共 API、状态/结果类型和依赖注入接口。
3. 在 `Src/Atom10ReloadFeed.cpp` 实现换弹与供弹状态机，确保各目标只写入一次、计时起点准确、错误不误报完成。
4. 增加不依赖真实硬件的单元测试或可替换 fake：覆盖正常时序、每个舵机写入失败、重复触发和边界时间点。
5. 将真实 Config/PEFExecutor/舵机适配器接入，并由上层 ARM 构建链验证。

## 6. 待确认事项

- 上层公共目录中舵机/IIC、时钟、Config 与 PEFExecutor 的现有接口名称、命名空间和线程模型。
- 目标角度和延时的配置类型与单位（角度表示、毫秒类型）。
- IIC 写入失败后的错误码/故障复位约定。
- 供弹动作在进行中再次触发时的处理策略。
- “动作组角度命令发送后”应以四次写入全部返回成功为计时起点，还是以首个写入开始为计时起点；当前方案采用四次写入全部成功后启动判定计时。
