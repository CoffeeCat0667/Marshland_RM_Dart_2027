# ATOM-14 Safety / Recovery 初步实现方案

- **模块**：ATOM-14_Safety_Recovery
- **程序**：Marshland
- **方案日期**：2026-09-27
- **依据**：本目录 `AGENTS.md` 及 `Design/Atomic/ATOM-14_Safety_Recovery.md`（同步基线 2026-09-26）

## 1. 目标与边界

ATOM-14 只负责安全、故障与恢复管理，不直接实现具体硬件驱动。模块职责包括：

1. 故障登记、查询、恢复状态更新、按配置清除及故障/恢复事件发布。
2. 普通执行器命令的安全闸门，尤其是发射机构舵机目标写入的拒绝逻辑。
3. 一般故障自动恢复流程。
4. WEB/SBUS 软件急停锁存、持续零力矩输出、人工确认解除及解除后的安全恢复。
5. 向 Motor、Charge、Reload、Fire、Servo 等 Atom 提出动作请求，并根据动作反馈推进状态机。

模块不负责：

- 进程入口或 `main` 函数。
- 电机、舵机、换弹机构、发射动作的底层驱动实现。
- 修改上层工程的编译器、工具链、平台或全局编译选项。
- 恢复原自动发射上下文；一般恢复和急停解除完成后均回到人工/手动控制语义。

## 2. 目录与接口组织

按工作目录规则采用以下实现布局：

```text
ATOM-14_Safety_Recovery/
├─ AGENTS.md
├─ CMakeLists.txt
├─ PLAN.md
├─ Inc/                 # 对外头文件
└─ Src/                 # 实现文件
```

建议的公共接口职责（名称可在实现阶段按现有工程命名约定调整）：

- `SafetyRecoveryController`：安全闸门、急停状态机和一般恢复状态机的统一入口。
- `FaultManager`：故障记录及历史查询。
- `SafetyPorts` 或等价依赖接口：抽象 Motor/Charge/Reload/Fire/Servo、配置、时钟和事件发布能力。
- 数据类型：故障代码/等级/来源/原因/时间、动作拒绝原因、恢复阶段及状态快照。

上层调度器周期调用模块的 `tick/update` 接口，模块本身不创建后台线程，避免引入未定义的调度和实时性假设。

## 3. 状态模型与关键不变量

### 3.1 建议状态

至少区分以下状态/阶段：

- `Normal`：普通命令按正常策略放行。
- `GeneralRecovery`：一般故障自动恢复进行中。
- `EmergencyStopLatched`：软件急停已锁存，只能执行安全动作。
- `EmergencyReleasePending`：已收到人工确认，正在完成换弹抬起和蓄力机构回零。
- `Manual`：恢复完成后的手动控制状态。

急停锁定优先级高于一般故障恢复；一般恢复不得覆盖、清除或绕过急停锁定流程。

### 3.2 普通命令安全闸门

所有普通执行器命令在送往底层 Atom 前经过统一判定：

1. 急停锁定期间一律拒绝普通执行器动作。
2. 明确拒绝任何发射机构舵机目标写入。
3. 急停安全动作和解除流程所需的受控动作必须走专用路径，不得复用普通命令放行路径。
4. 被拒绝的命令返回稳定、可记录的原因，并按需要发布安全事件/故障事件。

## 4. 一般故障自动恢复流程

按照设计文档的固定顺序实现为可观测状态机：

1. 分别请求蓄力电机 1、2 回零。
2. 仅当两个蓄力限位都稳定为低电平时，才离开回零等待阶段；稳定判定的周期/采样要求由 Config 提供。
3. 调用 ATOM-11 单次 `FireAction` 三次；每次成功后独立累计计数，失败则按配置进入失败处理，不得错误增加成功计数。
4. 三次发射期间锁定其他机构电机为零力矩，其他舵机角度保持不变。
5. 三次成功完成后，请求换弹机构抬起并等待动作组到位。
6. 整个流程完成后进入 `Manual`，不恢复原自动发射上下文，也不重新初始化系统。

每个阶段应具备：进入条件、已发出的动作请求、完成判定、超时/失败处理、故障登记和可观测状态。

## 5. 软件急停流程

### 5.1 急停锁存

- 只接受 WEB 或 SBUS 急停请求作为锁存来源，并将统一急停变量锁存为 `true`。
- 锁存后请求换弹机构执行安全抬起。
- 由周期 `tick/update` 持续发送两个 8 字节零力矩 CAN 帧：
  - `1.200#0000000000000000`
  - `2.1FF#0000000000000000`
- 帧周期、CAN 发送接口及多字节大端序规则从 Config/底层端口获得，不在 ATOM-14 内复制第二套配置。
- 急停期间拒绝全部普通执行器动作，特别是所有发射机构舵机目标写入。

### 5.2 人工确认解除

1. 只接受 WEB/SBUS 人工确认请求；禁止定时器、故障清除或其他普通命令自动解除。
2. 确认后再次请求换弹抬起，并分别请求蓄力电机 1、2 回零。
3. 同时等待：换弹抬起动作组完成，且两个蓄力限位均稳定为低电平。
4. 只有上述条件全部满足，才将急停变量置为 `false`。
5. 解除后进入手动语义，不重新初始化，不自动续跑被中断的自动发射流程。

急停零力矩输出、动作拒绝和人工解除条件应在接口层形成可测试的观察点。

## 6. 故障管理设计

`FaultManager` 以 Config 规定的字段和条件为准，支持：

- 登记单个故障的代码、等级、来源、原因和发生时间。
- 查询当前故障和单条历史故障。
- 更新单条故障的恢复状态。
- 按 Config 条件清除故障。
- 发布单条故障/恢复状态事件。

存储容量、历史保留策略、时间来源和清除条件不在本模块中自行猜测，统一通过配置或依赖接口提供。故障管理操作不得隐式解除急停锁定。

## 7. 依赖与解耦方案

通过窄接口或端口注入依赖，避免 ATOM-14 直接依赖具体驱动类：

- **Charge/Motor 端口**：请求蓄力电机回零、读取两个限位稳定状态、维持零力矩。
- **Fire 端口**：发起一次 `FireAction` 并反馈成功/失败。
- **Reload 端口**：请求换弹抬起并反馈动作组到位。
- **Servo 端口**：在安全闸门中拒绝普通目标写入，并保持非目标舵机角度不变的约束。
- **CAN/安全输出端口**：按 Config 周期发送两帧零力矩报文。
- **Config/Clock/Event 端口**：读取周期和稳定判定参数、提供时间、发布事件。

这样既满足“硬件操作逐项委托给其他 Atoms”，也便于用假端口验证状态机和安全不变量。

## 8. CMake 组织

本目录 `CMakeLists.txt` 提供可被上层 `add_subdirectory` 调用的 `atom14_safety_recovery` 目标，并提供 `Marshland::atom14_safety_recovery` 别名：

- 当前目录没有实现源文件时，目标保持为可链接的 `INTERFACE` 目标，便于先接入工程。
- 后续 `Src/` 出现实现文件后，自动组织为模块静态库，并公开 `Inc/` 头文件路径。
- 不定义 `main`，不覆盖上层工具链、目标平台、C++ 标准或全局编译选项；这些由上层 CMake 工程统一决定。
- 当前不修改上层 `NewVersion/CMakeLists.txt`；后续由上层工程显式 `add_subdirectory` 并链接该目标。

## 9. 实施与验证顺序

1. 固化公共数据模型、状态枚举、动作结果和端口接口。
2. 实现 `FaultManager`，覆盖登记、查询、更新、清除和事件发布。
3. 实现普通命令安全闸门及急停锁存/周期零力矩输出。
4. 实现人工确认解除状态机及两个蓄力限位、换弹抬起的联合完成判定。
5. 实现一般故障恢复状态机和三次 `FireAction` 成功计数。
6. 增加基于假端口的单元测试，至少验证：
   - 一般恢复顺序严格为“蓄力电机 1/2 回零 → 三次发射 → 换弹抬起 → 手动”。
   - 急停期间持续产生指定的两条 8-byte 零力矩帧。
   - 急停期间普通命令及发射舵机目标写入全部被拒绝。
   - 未人工确认、任一限位未稳定低或换弹未完成时不能解除急停。
   - 急停解除不重新初始化、不续跑旧自动流程。
   - 一般故障恢复不会覆盖急停锁定。
7. 在上层 ARM 构建链中进行编译和集成验证；本目录不执行独立 x86 构建。

## 10. 待实现阶段确认的输入

- 故障字段、等级、来源、时间和清除条件的精确定义。

- `FireAction`、换弹动作组、蓄力回零和舵机命令的现有接口及错误语义。
