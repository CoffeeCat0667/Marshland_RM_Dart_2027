## 2. 已重新同步的文档要点

### 2.1 模块边界

设计与 Guide 将 ATOM-14 的业务职责定义为：

- 故障登记、查询、更新、清除和事件发布。
- 普通执行器命令安全闸门。
- 一般故障自动恢复编排。
- 软件急停锁定、人工确认及安全解除编排。
- 急停期间零力矩安全帧的持续发送。

同时明确以下能力不属于 ATOM-14：

- `SystemMode` 权威判定和发射授权判定：ATOM-02。
- CAN 报文构造、解析和 SocketCAN 访问：ATOM-04 `CANAdapter`。
- PCA9685A、舵机通道和电机直接驱动：由对应硬件 Atom 负责。
- 四发自动流程和发次判定：ATOM-13 `PEFExecutor`。
- 硬件就绪门控、启动结果映射和外部输入唯一写入路径：`AppCoordinator`。
- 本模块不得包含 AppCoordinator/StateArbitrator/RuntimeCoordinator 具体头或持有其具体引用；通过确认后的窄端口/回调由装配层转发，公共调用端口尚未落地。

以上内容不在本目录实现，仅用于检查组装边界是否被破坏。

### 2.2 软件急停契约

Guide 明确急停是“确认”和“解除”两个独立步骤：

1. 外部 WEB/SBUS 输入由装配层上报并置位锁存。
2. `ConfirmSoftwareEstop()` 只完成人工确认及 `SOFTWARE_ESTOP -> MANUAL` 的模式迁移，不能视为急停已经解除；急停变量和锁存仍保持为 `true`。
3. 确认后完成获准的安全恢复动作。
4. 只有 `ReleaseSoftwareEstopLatch()` 成功返回后才算解除。
5. 锁定等待确认阶段全部电机零力矩；确认恢复阶段仅获准换弹/蓄力电机按恢复目标出力，其余电机零力矩，不用全零帧覆盖恢复出力；不重新初始化，不续跑原自动流程。
6. 不得使用 `SetSoftwareEstopInput(false)` 作为解除方式。
7. 再次急停立即撤销恢复目标并全部零力矩；恢复抬起再次失败进入 FAULT，保留尚未解除的急停锁存，不自动重试。

安全意图分类也必须保持边界：

- `IntentKind::SAFETY`：零力矩报文等不出力安全动作，锁定阶段允许。
- `IntentKind::SAFETY_RECOVERY`：换弹抬起、蓄力回零和一般恢复动作等出力型安全动作，按阶段允许。
- 不得用普通 `IntentKind::CONTROL` 代替上述安全意图。

### 2.3 零力矩帧契约

组装时必须确保实际 CAN 组帧/发送仍由 ATOM-04 负责，ATOM-14 只提供安全阶段和获准动作，不直接构造报文。锁定等待人工确认阶段：

- CAN ID `0x200`，DLC 8，全零数据。
- CAN ID `0x1FF`，DLC 8，全零数据。
- 周期见 Config（当前 20 ms），锁定等待确认阶段持续全部全零。
- 多字节规则统一使用大端序。
- 两帧均须发送，覆盖全部受控电机。
- 发送失败按 Config 进入错误状态并执行全机静默，不可静默忽略。
- 计时使用单调时钟，不使用墙上时钟。

人工确认进入有效安全恢复后，沿用这两组帧的结构，对获准换弹/蓄力电机输出恢复目标，同组未获准电机保持零电流；禁止同时发送全零帧覆盖恢复出力。再次急停或恢复失败立即撤销恢复目标并恢复全部零力矩；恢复全部成功才解除锁存。

本目录不得构造或解析 CAN 报文，也不得直接访问 SocketCAN。

### 2.4 一般故障恢复契约

Guide 和设计文档规定恢复顺序不可调换：

1. 蓄力机构电机 1、2 回零。
2. 两个限位开关均为低电平后才算回零完成。
3. 仅发射机构执行三次单次发射；每次按待机角度→发射角度→保持 100 ms→待机角度完成判定。
4. 三次发射期间其他机构电机保持零力矩，其他舵机角度保持不变。
5. 三次完成后执行双 M3508 换弹抬起；左右运行目标均成功后按 Config 运行 3 s，两台 0 rpm 目标均成功且无取消/失败才到位，继续速度 PID 保持。
6. 完成后进入 `MANUAL`，不恢复旧自动发射上下文。
7. 急停锁定期间不推进一般故障恢复。
8. `INFO`/`WARNING` 不应被自行升级为全局阻断；故障等级归约应复用状态仲裁提供的判定。

若换弹抬起再次失败，应进入 `FAULT` 锁定，所有电机零力矩、舵机保持当前角度、禁止发射且不自动循环重试。该逻辑不得在本目录自行实现。

### 2.5 换弹联动和故障管理契约

- 任一换弹电机离线、反馈/PID 异常或命令失败时，两侧均请求零力矩，并取消对应动作与计时。
- Config 中的 3 s 是正常运行时间，不作为无条件动作超时；硬件、编码器、CAN 和命令故障按 Config 登记。
- 普通换弹故障根因清除后可沿用一般恢复；`F-RELOAD-002` 恢复失败锁定优先，不自动反复重试。
- 故障码和等级必须来自 Config，不得自造。
- 历史故障按 Config 保留 1000 条、环形保留、最新优先。
- 故障事件记录 UTC 展示时间戳，内部等待/超时使用单调时钟；需要关联时保留两种时间基准，不把单调时钟纪元直接格式化为 UTC。
- 故障诊断不能成为修改控制命令的通道，也不新增故障清除 HTTP 路由。
