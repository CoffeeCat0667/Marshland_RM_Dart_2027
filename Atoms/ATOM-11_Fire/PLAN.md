# ATOM-11_Fire 实现计划

## 1. 目标与边界

实现发射机构的一次 `FireAction`：由调用方提供授权与前置条件结果，本模块负责将发射舵机按“待机 → 发射 → 保持 100 ms → 待机”的顺序驱动，并且仅在待机目标写回成功后报告动作完成。

本模块不负责决定是否允许发射，也不负责调度调用时机；授权应来自 ATOM-02/ATOM-13/ATOM-14。手动、自动和 PEF 故障恢复必须复用同一动作行为。

## 2. 初步设计

### 2.1 公共接口（拟放置于 `Inc/`）

- 定义发射舵机依赖的抽象接口：写入舵机目标、启动/等待保持计时所需的能力。
- 定义一次动作的输入上下文，至少包含急停状态、控制权、流程前置条件、发射舵机权限和发射/待机角配置。
- 定义分阶段结果与 `FireAction` 状态，区分前置校验失败、发射目标写入失败、保持阶段失败、待机目标写回失败和完成状态。
- 对外提供一次动作入口；禁止暴露会绕过安全校验的发射舵机控制入口。

### 2.2 核心实现（拟放置于 `Src/`）

按以下顺序执行，每一步独立保留结果：

1. 校验急停、控制权、流程前置条件和发射舵机权限。
2. 校验通过后写入发射角目标；失败立即返回，不得虚报完成。
3. 启动并完成 100 ms 发射角保持计时。
4. 向同一舵机写回待机角目标；失败时保持未完成状态。
5. 仅当待机目标写回成功时将状态置为 `COMPLETED`。
6. 发布一次动作完成事件，事件只能在上述完成判据满足后发送。

时间与舵机访问通过依赖注入抽象，便于在上层运行时接入真实驱动，并支持单元测试验证调用顺序和失败传播。

### 2.3 安全与验收重点

- 急停期间，无论普通调用还是调试调用，均不得写入发射目标。
- 无控制权、无流程授权或无舵机权限时，不得写入发射目标。
- 一般故障恢复由上层恰好调用三次本动作；本模块不自行重复调用，也不修改其他电机力矩或其他舵机目标。
- 验证动作严格为待机→发射→保持 100 ms→待机。
- 验证只有回到待机目标后才发送一次完成事件。
- 为每个普通阶段准备失败测试，确保失败不会产生完成事件。

## 3. 文件与构建安排

- 当前先创建模块级 `CMakeLists.txt`，提供可被上层 `add_subdirectory()` 调用的 `atom11_fire` 接口目标；待实现文件加入后再挂接实际源文件。
- 实现阶段创建 `Inc/` 和 `Src/`，不添加 `main` 函数。
- 编译标准、目标平台和编译选项继承上层 CMake 工程，不在本模块强行覆盖。
- 后续如需测试，优先由上层测试配置接入，不在本模块重复定义独立可执行入口。

## 4. 待确认/待接入事项

- 上层舵机驱动、计时器和事件总线的实际接口名称与生命周期。
- 发射角、待机角及舵机编号配置的来源和类型。
- 急停、控制权、流程前置条件及舵机权限的具体状态表示。
- 完成事件的载荷和发布接口。

在上述依赖接口明确后，再实现公共头文件、核心动作类和针对验收条件的测试替身。
