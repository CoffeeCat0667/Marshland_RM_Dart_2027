# ATOM-19 调试与校准实现方案

## 1. 目标与边界

ATOM-19（调试与校准）负责提供只读调试状态查询接口，以及由主状态机授权后执行的单步校准流程接口。模块不实现机械校准算法，不直接绕过 `SafetyManager` 控制硬件，也不因调试查询获得执行器控制权。

实现遵循以下约束：

- 不提供 `main` 入口函数；
- 头文件放置于 `Inc/`，源文件放置于 `Src/`；
- 编译标准和目标平台由上层 CMake 工程统一决定；
- 未在 PRD、Config 或后续设计中定义的校准项目、范围、参数和完成判据不得自行假设。

## 2. 建议模块结构

```text
ATOM-19_Debug_Calibration/
├── CMakeLists.txt
├── PLAN.md
├── Inc/
│   └── ... ATOM-19 对外接口头文件
└── Src/
    └── ... 接口实现与安全边界适配
```

建议将接口与实现分层：

1. **公共数据模型**：调试快照、校准步骤标识、步骤状态、失败原因及时间/序号等元信息。
2. **查询接口**：按设备或机构读取电机、编码器、PID、GPIO/限位、舵机、CAN、PCA9685A/IIC 和机构状态；接口只返回状态，不产生执行器目标。
3. **校准流程接口**：接收单步命令、授权对应机构控制器、维护步骤状态，并发布进行中/成功/失败结果。
4. **依赖端口**：通过抽象接口访问状态提供者、机构控制器、配置和安全状态，避免 ATOM-19 直接依赖具体硬件驱动。
5. **安全门**：普通调试/校准执行命令在急停、故障锁定或未初始化状态下拒绝；校准请求的模式进入由主状态机负责，本模块不强制要求调用前已处于 CALIBRATION 模式。

## 3. 核心流程

### 3.1 调试查询

1. 校验查询对象和请求参数；
2. 从对应状态提供者读取当前快照；
3. 返回只读结果及必要的有效性/错误信息；
4. 不调用执行器目标下发接口，不改变系统控制权。

### 3.2 单步校准

1. 主状态机将控制权交给本 Atom 的校准操作并进入 `CALIBRATION` 模式；
2. ATOM-19 校验安全状态、校准步骤是否已定义、请求参数是否符合配置；
3. 将步骤授权给对应机构控制器；
4. 发布独立的 `IN_PROGRESS` 结果；
5. 接收控制器完成通知并发布 `SUCCEEDED` 或 `FAILED`（含明确失败原因）；
6. 对重复、过期、未知或不允许的步骤请求给出确定的拒绝结果。

## 4. 状态与安全设计

- 每个校准步骤拥有独立状态，不用单一全局布尔值覆盖并发/连续步骤的结果。
- 校准状态至少包含：未开始、进行中、成功、失败；必要时补充拒绝/取消状态，但不得改变验收语义。
- 急停、故障锁定、未初始化状态下拒绝普通调试/校准执行命令；查询接口仍保持只读，是否允许查询由上层安全策略决定。
- 校准项目、参数、范围和判据通过配置/后续设计注入；缺少定义时返回“未定义/不可执行”，不以经验补全算法。
- 所有拒绝与失败结果应携带可诊断原因，便于上层日志和故障定位。

## 5. CMake 组织方案

本目录提供模块级 `INTERFACE` 库目标 `atom19_debug_calibration`，用于被上层工程通过 `add_subdirectory()` 纳入并链接。当前模块尚无实现源文件，因此不在本目录单独编译；后续出现源文件时，可将目标调整为普通静态/对象库，同时保持目标名和公共包含目录稳定。C++ 标准、编译器选项、平台检查继续由上层工程统一管理。

## 6. 验收与验证计划

- 静态检查：确认不存在 `main`，公共头文件位于 `Inc/`，实现位于 `Src/`。
- 接口测试：查询接口不产生目标下发；各类查询均能返回有效快照或明确错误。
- 流程测试：单步校准可产生独立的进行中、成功、失败结果。
- 安全测试：急停、故障锁定、未初始化时执行请求被拒绝；未知校准项目不会被擅自执行。
- 构建验证：在符合上层工程要求的 Ubuntu ARM/aarch64 环境中由上层 CMake 配置和编译；本目录不进行独立平台配置。
